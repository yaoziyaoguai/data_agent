# 公开合成座舱语音交互资料

本包围绕一条完整的座舱语音链路构造：唤醒或按键入口 → VAD 分段 → 端云 ASR 候选 → NLU 意图与槽位 → 多轮澄清 → 能力路由 → 动作提交与回执 → TTS → 播报、打断及反馈。导航、媒体、空调只是意图目标，不是独立业务大盘。

当前定义包含 **28 张 SQLite 表、421 个字段、14 份独立业务文档、26 项指标**。所有设备、模型、策略、命令与应答从零编写；没有读取或改名复用公司资料，不包含品牌、VIN、真实坐标、个人信息或原始音频，也不代表真实厂商的性能标准。

活动期为 2026 年 7–9 月，排他快照为 `2026-10-04T00:00:00Z`。缺失标签、未完成、取消、无语音、技术失败和未知结果分别保留。具体含义以[业务索引](business-guide.md)和字段字典为准。

## 文件职责

| 文件 | 用途 | 进入模型知识 |
| --- | --- | --- |
| `schema.sql` | 实际表、字段、主外键及约束 | 是 |
| `etl.sql` | 三张日汇总的实际加工；各目标有独立标记与血缘 | 是 |
| `documents/` | 14 份完整业务定义、字段字典、指标公式与限制 | 是 |
| `business-guide.md` | 范围、口径入口及文档导航 | 是 |
| `knowledge-manifest.json` | 明确允许列表、来源 ID、内容指纹和加工节点 | 加载元信息 |
| `semantic-catalog.json` | 由允许知识生成的表、字段、指标、文档和关系目录 | 是，仅派生允许来源 |
| `domain-spec.json` | 从零构造的数据规范和生成参数 | 否 |
| `generate.py`、`seed.sql` | 可复现的合成事实生成与初始数据 | 否；模型只能通过授权 SQL 读取数据 |
| `build_catalog.py` | 目录生成和只读核对工具 | 否 |
| `verify.py`、`verify_data.py` | 数量、引用、关系、时间和数据一致性核对 | 否 |
| `docs/dogfood/cockpit/` | 独立试用输入、数值参考、评分和报告模板 | 否 |

目录生成器只读取允许列表中的 DDL、ETL 和业务文档；不读种子、生成规范或评分答案。原文与内容指纹随 `source_bundle` 保存，每个字段都有表限定身份，避免跨表同名列碰撞。所有业务解释标为人工制定的合成定义、待核对状态；来源可追溯不等于指标语义已经被模型证明。

## 离线核对

在仓库根目录运行：

```sh
python3 docs/sources/cockpit/generate.py --check
python3 docs/sources/cockpit/build_catalog.py --check
python3 docs/sources/cockpit/verify.py
python3 docs/dogfood/cockpit/verify.py
```

生成器更新合成 SQL；`build_catalog.py` 不带 `--check` 时，按当前允许原文更新清单哈希、实际 ETL 血缘和目录。带 `--check` 时只比较，不修改。它在只有 DDL 的内存 SQLite 中核对每段加工的真实读取表，不需要读取种子或验收答案。

这些命令核对资料和参考的自洽性，不运行真实模型，也不把 Dogfood 标成通过。试用入口和给另一位 coding agent 的任务说明见[座舱语音 Dogfood](../../dogfood/cockpit/README.md)。

## 分析时必须区分

- 会话、轮次、阶段尝试、候选、槽位、逻辑动作和播放片段是不同粒度；一对多事实先分别归约，再关联。
- 入口、会话和轮次的业务日可不同；同日日表计数不能直接当作同批漏斗。
- 历史会话冻结 build 和策略；设备当前版本不能重标历史。
- 任务达成、标签一致、动作效果确认、TTS 成功、播报完成和用户正评是不同指标。
- ASR/意图标签仅覆盖人工合成子集；缺预测仍留在有标签有效分母，缺标签不补成负标签。
- 短操作以单调毫秒值为准；归一化逐字一致不等同语义理解，也未定义 CER/WER。
- 比例按分子/分母加权；P95 使用原始非空样本的最近秩法；零分母为 NULL。
- 超时或未知回执不证明动作未发生；重试及重复回执不能增加逻辑动作数。

所有例子只服务于这一虚构链路。数据中的相关性不证明因果，公开材料不包含任何真实公司或用户的案例。
