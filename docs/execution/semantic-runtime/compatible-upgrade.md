## 结果与范围

从升级前真实结构的合成应用库、v1会话/回执、旧冻结模型配置出发，升级后历史可看、未完操作可恢复、新消息用新合同。API/Worker/Pi/Web统一交付；公共索引一次切换，个人Mem0保持。

允许已有迁移/回填脚本、统一启动与配置模板、现有index target适配、恢复代码中有证据的修复、测试与文档。不得把用户主库当迁移演练库；不得删除历史、强推、发布、改真实配置或擅自启动旧writer。本包不是把01–07缺失的迁移推迟补写的理由。

## 演练步骤

使用 `SessionManager` 原生文件与公开接口承接旧会话；应用信封、工具合同、authority和业务Schema各按已有边界处理。打开/导入严格检查保留；同一会话内正常工具导出不恢复整本重读。不要通过手改Pi条目、重建session ID、复制另一份历史或删除损坏记录来让旧会话通过。

1. 核对实际待升级基线与部署版本清单；用可重复构建的专用合成库保存：旧来源/知识/引用、人工覆盖、旧有/无用途authority、终态分析和报告、个人记忆/Skill、未完成消息、已成功但丢回执工具、可能已发出的查询、旧model profile。记录指纹与操作ID，不复制业务主库。
2. 先在专用环境安装并启动支持新旧格式的统一API/Worker/Node/Web版本，暂保旧写入策略、旧索引目标和默认v1。跑01–04已实现的扩展/回填迁移，中途停止后续跑。验证身份/旧版本/引用数量及正文一致，namespace映射无碰撞。没有可靠依赖/采纳依据的旧记录保留unknown/null，不从自然语言猜回填。
3. 盘点现有source_snapshots、catalog_table_snapshots、knowledge_versions的实际读写消费者；源码中没有source_latest这一实现名，不能据Oracle泛称删除或改名。确认current回填/身份映射、依赖索引、旧精确修订读取、准备冻结输入、历史展示、authority和旧回执/输出恢复都就绪后，才切换新公共修订的latest-only写入；旧knowledge_versions原样保留。新修订只保留当前正文与必要版本元数据，任务/SQL/输出/账本/资产不变。来源缺旧全文不能用当前正文冒充。
4. 新公共Milvus集合从当前raw和有效知识准备；验证05真实REST能力、中文/过滤/尾部、重建无额外语义调用。使用现有目标配置切换一次，旧公共集合停写；切换间隙允许精确回读与明确index_lag，不建设双写一致性系统。
5. 在兼容统一版本、写入切换和新公共索引目标均已核验后，最后启用新消息v2，并核对四端版本一致；旧登记调用v1恢复。普通模型profile格式、tool_contract_version、authority dependency_schema各自版本语义独立，不用一个版本号控制所有东西。
6. 业务提交后丢回执、provider未知结算、query可能已发出、中断摘要、A任务已定稿B未完分别恢复；原operation_id/origin run/budget scope不变，不新增额度、重复查询或改成功回执。旧检查点缺必要身份沿原stale_context处理，不悄悄解除来源限制。
7. 回退演练限专用环境：停止新写，使用已验证兼容读取版本/仍可回源核验的旧索引，或从升级前一致备份恢复。新source/关系/answer_parts写入后，不直接启动不认识它们的旧writer。旧集合可查不等于旧应用可写。
8. 核对统一启动、取消、进程退出和资源清理；只清理本次PID/测试库/集合，保留账本与故障证据。修改启动器必须保留原本地开发方式和模型配置权限。

## 停止新全文写入前的实际消费者清单

编包基线中，以下读取仍依赖旧快照/版本表；实施时逐项核对最新源码并迁移，不能只删INSERT：

| 入口 | 迁移要点 |
| --- | --- |
| ingestion/store的catalog_candidate/catalog_upstream | 当前目录候选和上游读取仍取catalog_table_snapshots，迁到当前内容/兼容路径 |
| ingestion/store的effective_versions/read_source | source_heads联source_snapshots及指定修订读分别处理；当前修订完整性不能因没历史行而消失 |
| knowledge/store的persist/read/索引领取 | 指定当前修订也从knowledge_versions读，索引领取还冻结该版正文；迁移当前读取/版本元信息/实际索引输入 |
| prefill_materials的review及文档校验 | 当前input_json可能是裁剪材料，复核还会补读旧全文；03需冻结后续批次/复核真实需要的输入，不能只以已有input_json判定兼容 |
| context_authority、旧工具恢复、历史读取 | 04/06/07的用途和来源核验完成；旧正文缺失明确不可回读，不能换成当前正文 |

这只是受影响消费者导航，不要求另建通用迁移框架。回填、并发新写、索引/准备领取和重启都在专用库验证后，才通过本包切换门。
