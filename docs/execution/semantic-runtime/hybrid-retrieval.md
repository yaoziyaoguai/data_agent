### 2. 原位换成真实内容身份，闭合知识窄读

这是下一次实施的第一条主链，不能用给`read_entries_in_tx`加一个LIMIT代替。

**候选身份与排序：**SQL后备与Milvus沿用同一确定性索引投影定义的逻辑内容单元，不能仅把不同窗口装进同一类型就称身份统一。raw身份绑定record_kind、owner、SourceKey、修订、原locator及切块版本；knowledge身份绑定原EvidenceRef/entry-path、修订、适用的statement_id、规范窗口及投影版本。SQL产生候选时即返回此定位，不再以`sql:{object_id}`对比`entry:{fragment_id}`。同一身份在同一候选窗内跨通道/跨轮只计一次，但保留各通道排名；窗耗尽即释放本窗去重记录，跨新窗允许同身份重现（旧值：全查询history累计去重并有全局1000退休上限、跨窗恰一次；新值为已确认的候选窗生命周期，不新增服务器状态）；不同对象同文本、同对象不同位置仍为不同记录，hash只核验内容。

复用当前确定性分段和知识投影规则：SQL后备须在owner内推导相同规范片段，或读取已有同版本投影定位；不得将完整正文传到组合层重切，也不得根据query命中点另外制造候选窗口。先用现有字段/派生记录完成，不新增身份服务或永久映射表。实现时在CURRENT写明实际采用的投影函数、定位字段和SQL查询；若调整投影规则或增加statement身份，同时更新索引writer和reader及表示版本，不能让旧记录假装采用新定位。查询展示窗口可更小，但必须映射回规范候选；相交而不相同的窗口只做交付合并，不抹掉已消费身份。raw与引用它的知识陈述保留各自身份及同源关系。知识成功回执记录实际`projection_version`，同目标旧或缺失版本仍报告索引覆盖incomplete；此检查不自动重领或改绑原operation/attempt/profile/trial。新公共集合准备与统一切换仍归08，不能将覆盖缺口修成隐式全库重建。

**内容选择：**共同排序先选真实内容项，再调用owner。知识owner只接已选entry/statement/window，不再将向量hints与所有query词做OR后返回整个命中entry。SQL可在库内匹配大正文，但下行只包含选中位置及必要支持；数据库扫描成本和下行字节分别报告。`StageReads`缓存、失败集合及共享30名额使用同一内容身份。后到同对象新entry需要补读；同一位置命中重复复用。失败/失效仍占实际读取名额，不退款。

**投影输出：**entry/statement窗口使用其原正文的Unicode字符坐标，保留到原ref/path补读位置的映射；文档raw仍按所有有效entry以`\n\n`拼接的原坐标，检索附加标题/背景不进入offset。返回原总长度、修订/hash，以及绑定到该内容单元的完整有效性核验依据、实际贡献来源和最终可见内容的登记依据，三者不可混同。已存映射能细分时按映射处理；legacy只有对象级必要来源时保留原核验，不能因正文裁小就推窄来源。整项被回执裁掉后不登记该项，但保留下来的legacy项仍携带其完整必要依据。结构读取复用本轮引用投影，不扩大为整对象/关联表快照；相关结构内容如需交付也须经过对应内容读取，不借元信息接口偷偷返回大SQL。

**v1适配：**公开v1仍按原对象/entry形状返回，但只是最后的显示聚合；不能因此把同对象多个内部内容项只计一个。`attach_matches`、`search_preview`、同版`read_knowledge`补读必须使用原定位；裁剪后的状态与依赖登记按实际可见内容，不把支持ID当已交付内容。公开v2的命中分支/游标编码仍属06，本包不新开端点。

先红后绿的反例：同对象很多同词entry、单个巨大命中entry中的小窗口、非首entry中的非首statement、词法先到E1而dense后到无字面词的E2；SQL展示窗口与Milvus窗口不同但对应同一规范record时只计一次。固定所选位置，只扩大未读正文和关联表SQL。均走正式工具登记→执行→回源→最终核验→裁剪保存；同时验证原ref/offset补读、投影外必要来源在锁外换版、最终回执裁掉内容后依赖不多登记。

各分片后页按后端实际消费位置推进，不按去重数、有效数或交付数推进；SQL也返回真实消费位置和耗尽事实。当前预留耗尽可能只是另一请求在途，统一owner应在处理该请求结果后按实际剩余额度决定是否继续；不能把一次临时无额度永远标成已穷尽，也不需要新增等待服务。

- 可交付数量来自**当前有效的已读内容**，不能用元信息对象数或failed读取数判已够。有效主命中不足且还有读取名额时，无效正文驱动后页；已有必要支持要求的定点补取沿原支持路径。30耗尽就停止新主命中读取，但继续从共同次序收集已有有效内容，不能遇到未读高排项就break丢掉后面的已读项。
- 保留查询向量直到本次检索结束，dense后页沿真实Milvus offset推进；不重复请求前缀。共享五个深度轮包含首轮，允许集分片不是额外深度；未发出的第六轮不计入报告。dense晚到不另得五轮。
- 在途请求与已收唯一记录合计受1000上限约束，不能超收后截断/clamp。失败请求释放未使用预留，已收身份不因失效或合并退款；SQL和Milvus沿上述同一身份口径。
- 某片失败只结束该片，健康片仍可前进；已有成功BM25分片/页时保留partial，不再加SQL票。成功空也不启动SQL。
- **整条BM25明确不可用时，同一owner立即启动SQL首批；SQL替代词法排名，与dense进同一次RRF，不成为第三票。** 移除当前末尾才查询SQL的职责，而不是给dense设配额或多建后备循环。SQL保留原范围和先相关性后截断，不回到全库top-k后过滤。
- **继续分配正文读取前先处理已经就绪的通道；任一后续页慢时，另一就绪通道仍能核验、排序和回源。** 不能只在`advance_candidates().await`之前查一次`is_finished`，然后整段等待。沿当前调用内future/select和现有游标处理，异步工作有明确所有者与收尾；不要新建调度器、永久任务表或后台结算Worker。

“SQL强项必须交付”的验收固定事件：BM25明确不可用，SQL首批在主命中额度耗尽前已就绪且排名应选中，正式回执须含其正文。SQL确实迟于额度或期限时，保留真实未覆盖/未交付定位，不要求退款、追回名额或无条件挤走已读项。

### 4. 补齐全链期限与错误出口证据

检索边界在首次范围准备前创建一个10秒绝对期限，所有子调用沿用它，不因无launch、换通道或后页重新起算。覆盖允许集、anchor/索引目标、Embedding、元信息、SQL后备与owner内容。只读调用可用剩余期限取消并沿sqlx正常清理；每次新工作前检查，晚于期限取得的正文不能交付。最终权限/版本/运行身份重核与已发Embedding收尾可以在期限后完成；10秒不是包含必要结算的严格HTTP SLA。

本轮局部修复不能代替全链证据。独立延迟范围准备、元信息、正文读取及账本结算，记录具体开始/完成/期限次序：范围准备消耗8秒后只剩约2秒；已读A后B跨期只交A；已发Embedding结算被DB锁延迟时工具必须等其收尾后返回；读取阶段普通数据库错误同样不能丢下结算，也不能因错误返回时跨期便吞为bounded。账本可写的成功、已知未发送、阻塞后恢复夹具，断言响应时原operation/attempt无issued；禁止响应后轮询变好冒充通过。结算存储本身失败时返回明确错误并沿原身份和既有恢复规则处理，不报成功、不猜零消耗、不换身份、不新增无限重试或后台恢复器。

保留两个通道首批以及后页的反向慢测试。Milvus当前单请求8秒超时，若要真实覆盖10秒期限，测试须用多分片/后页等明确事件条件，不能把单个15秒代理延迟误称整个调用必达10秒。覆盖状态可以是已有合同的bounded/candidate_limit，但必须按事实表达，不能把成功空、失败、耗尽混为一谈。

许可前超期不领许可；许可已提交但确认未发送时沿原finish零消耗结算；已发送按实际或unknown结算。历史unknown不等于本次未发送，不能零结算或换身份重发。`budget_unavailable`（未配置）仍允许词法降级，存储/权限/租约等错误不能一并吞掉。

### 5. 用同一个实现完成内部双类型交付，再关闭05

前述内容身份和组合入口稳定后，把`include_raw`/可交付类型传进**同一个正式组合用例**，不要调用另一条模块search后手拼原文。raw与knowledge在同一RRF层按相关性全局交错，不能先各取配额，也不能把第一次融合分数当第二次投票。必要支持不被普通related挤占。

公开v1仍仅知识，且该限制在召回/计数前生效；内部双类型按SourceKey、修订和窗口向ingestion/knowledge各owner窄读，实际内容与核验依据一同进入`ScopedSearchStage`和原最终提交检查，保留全局次序、已读/未交付定位与覆盖事实。补raw锁外回读之后来源换版的组合反例，必须拒绝旧内容，不能只检查raw数组有值。内部结果不能伪装成已经发布公开v2。
