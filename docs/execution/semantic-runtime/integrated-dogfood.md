# 两条主链和复杂语音座舱验收

前置：08升级演练通过。需求重点 D03/D04/D05/D06/D08/D09/D13/D15/D16/D17、C01–C08及相关A项；其余能力按[覆盖表](coverage-and-validation.md)回归，不删除映射。真实用户邀请/发布D18另按授权。

## 目标与边界

证明一般流程可用：资料同步→原文/整理→检索取证；用户多轮→澄清/SQL→明确执行→结果/答案→历史复用。通过的单位是实际场景及其证据，不是“所有功能已完成”的口号。

复用 [语音座舱试用包](../../dogfood/cockpit/START.md)、manifest、scenarios、既有100项与独立参考。公开合成资料仍是语音链路，不回到旧零售样例，不凭记忆补业务定义，不引入公司信息或原始音频。产品中不得写特定案例名称/答案/固定调查策略。

## 分层推进

1. **无付费准备与工程检查。** `make verify-cockpit verify-fixture`，`python3 docs/dogfood/cockpit/reference/check_reference.py`；核对当前来源清单、输入允许列表与独立答案隔离。`--check`和`--audit`只校验材料/既有证据，状态仍是未执行新真实样本。
2. **本地完整链。** 在专用合成应用库、平台及本地provider中跑01–08关键路径与故障反例；用真实Rust/Pi/MySQL/Milvus边界，不用UI拦截伪造成功。通过只记工程/模型替身证据。
3. **真实模型代表样本。** 先核对接手会话实际费用、端点和模型授权；缺授权时把该层保留blocked_authorization并继续无需授权的工作。获准后先跑P01–P09前置，再S01→S02和一个有语音口径歧义的多轮场景；确认实际模型、思考档、Pi版本、来源/索引指纹和工具合同。单消息24次/连续临时失败3次保持，套件不另加累计次数上限。
4. **逐级复杂与回归。** 代表样本确认后按既有L1–L6推进；优先重跑本轮所有受影响失败根因及其邻近反例，再完成既有100项中适用的回归。标明每项本次pass/fail/partial/blocked/inconclusive/not_run；不得把历史通过抄为本轮通过。
5. **问题修复与复验。** 实施agent可修本轮一般原因，回到所属包的窄检查/独立审查，再重跑受影响轨迹。执行dogfood时保持输入/预期冻结；不能边改题边声称通过。发现新产品需求记候选，不乘机扩范围。

本实施包的agent具有实现职责，区别于旧试用手册中“只试用不修代码”的角色：试用阶段不改参考答案；确认根因后以独立修复增量处理，再重新试用。不能把同一次运行中替换输出当作原轨迹通过。

## 必须补充的综合轨迹

| 轨迹 | 步骤与观察 |
| --- | --- |
| 空库到可回答 | 导入表/字段/完整生产SQL和任意文档；暂停语义整理但完成raw索引；问只在长文末尾的定义；检索/补读后给答案，不能先通读全文 |
| 来源更新与人工保护 | 同步纯SQL排版→无修订/重整；再改真实必要条件→相关语义待重整/当前采用即时核验；人工覆盖保持，旧报告仍可历史查看 |
| 时间与口径续接 | 先限定ASR候选选择口径、截点和来源；仅改月份；查询草稿/执行/结果都沿正确条件，缺采纳则澄清，不心算替代数据库 |
| 互斥来源的双任务 | 同一条消息A只用A、B只用B；A定稿后中断B；恢复完成两答案；检查真实provider输入、数据库引用及刷新后最终文本 |
| 长会话原生压缩 | 累积多轮、工具和历史投影，触发Pi压缩；同会话续接、旧条件/操作/预算保持；摘要输入与两段cap符合配置；撤权内容不残留 |
| 检索与支持容量 | 同表多个强字段＋弱类型、1200候选、超128片段；跨段例外；小回执多页；最终数字或结论依据完整，状态/游标无误报 |
| 查询晚到与历史 | 执行原条件查询后改条件/开新任务；旧结果晚到仍归旧任务；普通语义改版可复述历史，当前再分析重新核验，结果过期不自动重跑 |
| 个人能力保持 | 明确可复用纠错→Mem0回源；记忆编辑/停用；显式选Skill/原生read；目录分页与来源限制；不扩选用权、不把私人内容公开 |
| 大容量真实边界 | 验证获准端点实际8MiB接收和600秒链路/取消；不能通过把全部问题塞满窗口来人为验证，按可控合成请求分层记录接收/质量证据 |

复杂分析仍包括首次/最终成功、分母去重、NULL/未知与零、跨表一对多、按构建/网络分层、结果占比/贡献、多轮澄清及“有关联但不能证明因果”。独立预期来自已有业务规范与参考计算，不能倒推模型输出。

## 证据与收尾

沿用 `records/results-template.json`，在 `.local/dogfood-runs/<run_id>/` 保存实际输入、SQL/参数、工具/输出引用、模型请求边界证据、截图、每次attempt和HANDOFF。授权配置与凭据不进公开记录。报告按根因聚合，同时保留全部受影响case；重试成功不删除失败尝试。

需要的性能只记录实际小/大目录、候选/回源工作量、延迟和覆盖限制；不建设新的观测平台。真实模型、合成平台、真实数据平台各自写明；真实平台不在本轮实现范围，不能因此谎称已接入，也不阻止说明合成环境已验证范围。

最终更新README、开发文档、系统/实现设计的已实现与未验证状态、相应架构图源/生成图册、原dogfood操作说明；不让目标图继续冒充现状图。图源改变再运行 `node docs/architecture/render-implementation.mjs` 并看桌面/手机，随后 `python3 docs/architecture/check-implementation.py`、材料/链接检查。

验收全部对应需求且独立复核后关闭当前增量。若真实模型未授权/未通过，代码实现可分别报告完成，但整套真实效果验收保持缺口。提交/推送/部署/用户服务更新只按接手会话实际授权执行；最终报告必须给代码状态、证据层级、未完成项和可复现入口。
