## 3. 100元怎样真正管住

### 费用范围和账户

100元是本次所有新增产品API费用之和：聊天、Pi压缩/恢复/重试、结果解释、语义预填/整理、共享embedding、Mem0提取及索引/检索、获准的第二模型样本。外部coding agent自身订阅不是本应用可计量账本；Oracle网页审包也不是产品模型测量。不得购买新账户/云资源。

本次新建唯一QA run身份和独立试用配置，所有子账本登记到本轮清单；这是新获授权的QA任务，不得拿换run/trial作为追加额度方式。旧试验库、原13次费用与unknown/预留不清理、不重置；旧调用的历史费用不算本轮新增，但本轮若恢复旧操作产生费用仍需计入，所以默认不启动旧执行者。

优先沿用当前 DeepSeek Flash/high、hybrid、Qwen共享向量和真实Mem0。保留锁定Pi版本、实际有效的大窗口/输入/输出/请求体配置，不退回旧模板的小窗口来省钱，不改每消息24次、连续临时失败3次。其他已配置模型/协议只做必要配置与切换代表，不开展模型排行；凭据/网络缺失记阻塞，不能擅自开通新付费供应商。

### 开始付费前必须完成的核对

1. 在本轮 `budget.json` 记录授权来源日期、100 CNY、开始时账本值、所有可能外发通道→持久trial映射、型号与冻结费率、汇率/支付费用依据及上限。每条通道还记录两列：**预留上界依据**（输入上界、实际生效的输出上限、冻结费率及其他收费项），**派发约束依据**（每次新增收费派发，包括重试/恢复/辅助调用，都先取得相应预留）。只记凭据文件引用，不记值。已有应用账本按USD micros，不能把100写成100美元。
2. 在执行当天查实际支付/官方汇率来源，以 **不低于8 CNY/USD且不低于已核换算及支付费用上界** 的值作本次预算汇率 `r`；8是记账保守参数，不是市场汇率声明。拿不到可靠费用上界时，阻塞该付费通道，不猜价格。人民币报价先按同一冻结规则转入账本。
3. 本轮全部持久子账本的人民币额度之和最多 **95元**，余下5元不自动分配，用于换算/结算差异余量；绝对支付授权仍是100元。建议聊天及共用其账本的辅助调用80元，共享embedding等独立维护通道15元；若实际拓扑有其他trial，在这95元内拆分，不能给每个trial都设95元。USD micros总额度不超过 `floor(95 / r * 1_000_000)`。
4. 复用现有Rust账本的 `spent_micros + reserved_micros + next_reservation <= cost_limit_micros` 派发前限制；同时清点聊天、维护与Mem0是否全部经过它，预留是否足以覆盖实际请求可能发生的费用。仅有总额比较不证明预留足够。复用当前调用点、预留算法及匹配版本的无费用拒绝证据，不逐场景新造测试；不能证明的通道保持关闭，不先用官方请求试价格。单独后台通道要有持久限额。unknown占用和在途预留不释放、不当退款；启动前、每条完整轨迹后和退出时汇总各账本，不能靠测试末尾才算钱。
5. 核对所有本轮trial的 `expires_at`、调用次数及费用限制。正常聊天用现有request模式并显式填累计费用上限，不沿用旧48次小样次数作为本次覆盖上限。共享embedding及非request模型trial当前默认1小时；同ID重新注册不会延期，改profile还可能触发指纹冲突。先选合理且足够本轮的有效窗，不修改产品默认值、不换ID续额。既有代码没有统一延期CLI：确有需要时，在准备阶段通过本项目现有MySQL运维连接，对已由应用登记、属于本轮的新trial一次性执行 `UPDATE model_trials SET expires_at = :qa_end_utc WHERE id = :qa_trial_id`（参数绑定到实际ID及UTC截止时间）。先暂停本轮会产生新调用的进程，保存整行before/after，确认只改变到期时间、次数/费用/预留/状态/指纹不变，再接回同一实例。request模式原本无到期时间无需修改；不要触碰旧trial。若不能可靠完成，先在原有效期内测试该通道，到期停止，不能将预算配置到期误报为模型故障。必填的辅助调用次数上限按本轮资料规模预先配置并记录，不能运行中改profile补额。
6. 在本轮隔离配置上，复用匹配的本地协议/预算测试证明超额请求会在外发前拒绝。**首次外发前限额必须已生效**；若登记发生在启动过程中，要有现有调用点证据证明先持久登记、预留，再发送，并在启动后立即读回。仅写“最多100”或轮询费用不算硬限制。全部收费路径未被覆盖前不启动那些路径。

费用核对代码入口是 `apps/agent/provider/controlled.ts`、Rust `runtime/model_calls`、`runtime/provider_calls`、`use_cases/knowledge_embeddings.rs` 和 `apps/memory/providers.py`。Mem0的 `_call` 先向Rust申请issue并核 `send_allowed`，再发送；当前聊天预留按冻结 `profile.input_limit` 与实际输出cap，Rust要求该输入上界一致。记录预留与实际usage的区别，QA不改预留算法，也不把整个context window或一次实际输入随意替换进合同。

额度在首个真实样本后按实耗估算覆盖能否完成。优先做未覆盖能力，不在同一简单问题上反复测；预算不是必须花完的目标。达到已承诺额度、出现超额/不明外发、计费与预留无法核对时，停止本次新的付费动作并采证，保留在途身份。已有可用余额不能证明一条长请求可以发起，仍以预留门判断。不要通过降低正常容量配置来绕过预留失败。

| 本轮资产清理与依赖提示 | G10 | 所有依赖结束、证据落盘后，逐项停用/安全清理本轮资产，观察依赖失效提示；不删除失败现场、旧账本、基线或他人资料 |

第一轮先核实际页面、管理入口和当前工具目录，把已开放动作对应到此表。发现表内未列出的现有能力，补入本轮探索记录；不能因旧手册没列就跳过，也不借此实现新功能。对主要交互观察正常、空内容、进行中、可恢复失败、取消/返回、刷新和权限差异，按真实流程组合，不穷举状态笛卡尔积。

正常链通过后，依赖具备就尽早完成§6 Skill链及至少一条复杂综合轨迹，优先核多任务隔离/中断的 `isolated-task-answers`；观察前提不足时先测 `time-and-definition-continuation`，原复杂项保留未完成状态。随后交错推进各能力代表、原100项、10轨迹与自主探索，按依赖和覆盖缺口安排，不等100项扫完才做综合能力。G10始终在其他计划动作及证据落盘之后，不能为清理打勾破坏仍需恢复的现场。

每类至少一个真实可观察路径是目标；预算/依赖停止条件优先，包括Skill链和“至少6个探索”也不能强行做满。预算有限时未覆盖类别优先于同类重复，Skill全链优先于大规模索引压力。每项都必须在最终记录有状态，未实际执行不能计入通过。

长会话用真实调查、补查、条件变化来推进，不机械复制长垃圾文本、不缩小正常窗口迫使压缩；未实际触发原生压缩就标该真实子项未验证，已有工程证据另列。千表只是底库规模，不能把全库塞入提示；需要规模试验时复用安全可用的已建索引，初次索引、恢复重建与单次检索时间分开。预算不足不重新全量建库求一个打勾。

## 6. 让Data Agent自己生成并使用Skill

这条链必须实际执行，不能仅靠代码/旧案例判通过。名称使用本轮前缀，如“语音链路对比核对法”，不要把验收case编号带入产品方法。

1. 先让Data Agent在一个对话中完成真实的ASR最终尝试率及首播时延分析。口径来自产品可读正式资料，使用者先看草稿再明确执行。操作者用独立参考核数值与解释，错误分析不能当成合格方法的依据。
2. 在同一对话请求：“把刚才的分析步骤整理成可复用的个人方法草稿。保留适用范围、粒度、分母、时区、单位、缺失与取消例外；月份和筛选作为参数，不固化本次答案，也不要自动执行后续SQL。”观察产品自主使用 `prepare_skill_draft`，回执引用实际本人同会话依据；模型口头说已创建不算。
3. 在“我的积累”阅读草稿及依赖，核对后明确保存，记录Skill ID/版本。可通过正常界面修正真实缺陷，但原草稿问题要单独报告；不能把外部agent手写的完整正确方法覆盖上去，冒充产品自主生成成功。
4. 新建对话，在产品UI明确选中该Skill，提出另一个月份/语言条件下的同类问题，先只要计划/SQL。确认实际采用原Skill版本及必要附件/依赖：`read_knowledge`仅交descriptor/native_path，不等于正文已用，须有Pi原生读取或实际正文加载证据。SQL随新条件变化，未自动继承执行授权；再按正常明确消息执行并核结果。不能仅凭回答“已使用Skill”判通过，也不把技能正文粘进提问。
5. 再用一个新会话做未选中对照：不要求它“回答更差”，只确认未冒称或暗中采用该私人Skill。让Carol尝试访问Bob私人方法；正文/附件不可泄露。
6. 在本轮合成空间明确发布独立公共副本，记录两个ID；修改私人方法后公共正文不变。Carol明确选中公共副本执行一个相关任务，核实际采用和来源。公共副本只能含已检查的公共合成语义，不能夹带私人记忆、聊天原文或独立验收答案。
7. 最后停用本轮私人方法，重开对话/刷新后不能继续作为有效Skill采用；已有历史引用保留其历史身份。附件读取、建议与版本失效可借A15/相关轨迹覆盖，未实际分页不能称续读已测。

`skill-lifecycle.json`记录每步输入、资产/版本、采用证据、源依据、实际任务结果与局限，作为附加轨迹。A04/A05/A14等只有满足各自原输入/全部断言才可复用同证据；不把这一条链自动算成原100项全部Skill用例通过。独立参考答案、expect、生成器、其他测试报告严禁进入Skill。

## 7. 自主探索与已知回归

执行者在第一轮观察后提出至少6个有理由的探索假设，落盘后再执行。方向可取：

- “解释这个选项”之后才补自由回答，再切换另一个目标，观察澄清归属；
- 同消息三个问题、两个条件来源不同，只授权其中两项，完成顺序反转；
- 仅改时间/时区/语言，前一查询结果晚到，报告仍绑定原条件；
- 不同表同名字段、相同概念别名、文档尾部“首次/最终/除外”限定，允许共享定义而限制分析目标；
- 语义更新期间继续阅读/查看已保存结果，区分旧分析可看与当前采用；
- 长会话后显式选择Skill、临时覆盖记忆、暂停/恢复自有进程，核参数/来源/费用身份。

每条先定义可观察预期和独立依据，不把未定义口径写成断言。适度使用自然、含糊、多目标、纠正、否定和撤回表达；目标是现实使用，不造极低概率故障排列组合。用已有合成故障入口控制取消/未知/恢复，不改产品。失败优先保留原状态；能安全恢复相同初态才做一次有价值的复现，LLM随机失败不能通过反复换话术洗掉。

旧零售`run-business-acceptance/S02`与本包`cockpit/S02`不是同一题。前者的匿名客户越界解释列为额外回归，按现有conversation模式在其独立资料集/子预算中测一次；实际入口须限定 `--interaction conversation --cases S02` 并绑定本轮子预算，无法绑定则只阻塞该项。`check-business-conversation.mjs`的 `--check` 固定断言官方请求0，只是协议接线证据。不要把零售夹具导入座舱实例、不覆盖原真实报告、不把这次成功记进座舱S02。额度不足时保留已知问题，不让它挤掉整类新能力。
