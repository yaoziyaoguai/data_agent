## 4. 证据分层与审查

| 层级 | 可证明 | 不能替代 |
| --- | --- | --- |
| 文档/Schema/生成检查 | 计划、类型和材料一致 | 实现行为或模型质量 |
| 纯函数/协议替身 | 容量推导、状态和边界合同 | 真实模型自主理解 |
| 本地API/Worker/Pi/MySQL | 实际事务、恢复和工具链 | 真实平台接入 |
| 实际Milvus/embedding | 当前版本REST、索引、范围、规模成本 | 所有部署规模/检索质量 |
| 获准真实模型＋合成平台 | 指定模型/配置/题目的实际能力 | 其他模型、全部问法、生产质量 |
| 真实平台/用户试用 | 对应实际环境与范围 | 未执行的其他能力 |

每条结果保存命令或原操作、退出码/完整结果、代码与资料指纹、环境和证据路径；超时/日志截断不是pass。付费不足、环境缺失分开标，不改测试预期过关。

检查器审查JSON要求reviewer、summary、conclusion及scope_sha256，字段以当前 `scripts/check_delivery.py` 为准。只有实际独立审查者确认该内容后才能写passed；主实施者可整理格式，不能伪造他人结论。实现或验收范围改变后重新做受影响复核/指纹，不复用过期通过。

每包结束在CURRENT留下：包/增量、目标和非目标、实际变化文件与公开接口、迁移状态、已跑命令及证据、独立审查、未验证层级、下一包入口。授权与环境只引用当前会话有效信息，本地私有路径/身份放忽略目录。

中断时还要保存已发送/未知操作、sync/任务/查询/索引/运行ID和原budget scope、失败假设与下一检查。恢复先查原状态，不重发未知操作、不重置数据或次数。各包不另维护一份CURRENT。
