## 4. 修目录读取的确定性问题

### 4.1 同页刷新只保留一个在途批次

入口：`apps/web/src/features/knowledge/KnowledgePage.tsx::refresh`及两个刷新effect；`apps/web/src/shared/api.ts::api`。读[实现设计](../../architecture/implementation-design.md)的维护目录/分页约定和当前页面保存回调。

已证：固定2秒`setInterval`不等Promise.all结束；每次都递增generation。慢响应不仅形成重叠请求，还可能被下一次generation持续判旧。每批又拉第一页、建议、权限及全部visibleObjectIds。

修改边界：

- 把固定发车轮询替换为完成后安排下一次刷新，所有刷新触发共用本组件的在途状态。保存/同步完成时要最终看见最新状态；如当前已有刷新，合并为一个待刷新标志，完成后补一次即可，不丢手动意图、不累计队列。
- 一批读取的生命周期覆盖它实际发出的全部子请求；`Promise.all`首个reject不代表其余请求结束，不能此时清在途标记并再次发整批。沿本批取消/收尾处理即可，不加全局重试或请求注册中心。
- 用户、页面生命周期变化或卸载时停止后续调度，取消不再需要的读取并忽略晚到结果。若需要，在现有`api`薄接入增加可选AbortSignal，不改所有调用方、不建新的client。取消不能被显示成业务失败；真实读取失败仍可见并保留已有内容。
- 合并目录和可见对象结果时保留已加载分页、选择、编辑中的草稿和现有版本比较。第一页已带完整对象时不重复按同ID发detail GET；第一页之外或确需详细内容的对象保持读取。
- 不新增SSE、全局缓存、React Query迁移、动态退避、页面可见性调度框架。仍保留正常维护进度更新，不通过取消自动刷新或缩成两次加载来“通过”。

最少验证：扩展现有浏览器用例（优先`check-knowledge-experience-browser.mjs`或已有相同责任的脚本），以可控的>2秒响应证明不会叠加刷新且最终显示；同一场景里完成一次保存触发，证明未丢刷新，离开后不再产生新批次。沿旧用例验证迟到结果不串用户、分页与编辑草稿不被覆盖；不要另铺一套全交互矩阵。模型请求应为0。

与4.3同责任的正常打开/离开观察尽量复用这一组产物；受控延迟证明行为，当前隔离语音实例观察证明本次环境，不把两者再展开成重复矩阵。

### 4.3 对历史池故障只做有界复核

在同一隔离实例、代码加载一次后，沿已有正常目录、请求中离开、连续打开/离开三条普通路径观察；不加并发压测矩阵。保存请求开始/结束、重叠数、相关事务及普通API是否恢复。取消fetch不等于服务端任务已停止，只有观察到的事实才写结论。

如果仍出现PoolTimedOut，第一次复现就在同窗采集一组池size/num_idle、请求持有方和DB等待证据；能够定位时只修已证原因。现有日志不够时仅加必要的局部诊断，收尾去掉无用探针。证据仍不足则交付有限诊断、缺失信息及当前阻断，不自动追加观察轮次或试验矩阵。禁止无证据扩大池、超时或重试。

历史PoolTimedOut与S05首次失租分别记录，不能互相代证。完成各自相关的有限核对仍无法追溯时，可以将调查记为“有限复核完成，根因未确认”，停止调查；旧attempt状态不改，不宣称根治。S05已有准备期回归只证明该一般缺陷修复，不重发原失败链。

当前必要路径若仍失败，继续阻断。若21项核心、来源轨迹及适用工程出口全部满足，只剩无法追溯的历史API因果，向用户提交“是否接受该已注明遗留而完成核心交付”的具体选择，并停止重复排查。本包不自行撤销CURRENT已明确的API阻断，也不要求靠无限重试获得一个无法恢复的历史答案；无需为了这项未来收尾选择暂停其他已授权工作。

## 5. 来源规则收敛，不另造权限系统

必读：实现设计17.4、`source_identity.rs`、`source_limits.rs`、`resources.ts`和`data-tools.ts`相关描述；原来源轨迹、`source-authority-real-recheck-diagnosis.json`与本轮审计的只读观察。

### 5.1 删除分析目标与证据许可的混同

逐一替换`resources.ts`的“来源或业务域限制”和“用户限定的域、对象或资料范围须贯穿所有检索/补读”，以及`data-tools.ts`中`AnalysisUpdate`、`source_identity`的相关冲突说明。按任务目标、来源许可、来源身份分别表达，不只修改两句含“业务域”的文字而漏掉相反规则：

- “分析ASR/只统计ASR指标”决定分析目标或检索定位，不自动禁止共享语音定义。
- 用户明确限制“仅依据这些资料/不得读取其他来源”才形成来源允许集；否定、例外和“相关定义”仍由Pi理解，宿主执行已保存的稳定SourceKey范围。
- 明确限定的证据来源须贯穿检索和补读；分析域、统计对象、SQL表过滤本身不新增来源限制。Agent自选的定位过滤可调整，用户的任务条件不能擅自取消；正文读取仍受保存的允许集约束，扩大该集须有明确决定。
- 同名表的知识对象身份与资料来源身份不相同。source_identity只提供候选和真实贡献根；不能把schema/business-guide聚合来源冒称单表，也不能把某对象的一部分根当完整来源。
- `roots_complete`只证明真实贡献根已核全，不证明范围符合用户许可，更不表示正文已经读完。新任务明确没有额外依据限制才可声明null；已有任务未修改来源时继承原限制。同步修正`search_knowledge(view=source_identity)`的身份说明，避免与任务工具互相矛盾。
- 找不到足够细的合法来源或范围内缺必需依据时，说明具体缺口、请求必要的范围选择。禁止自动null、扩大到整包、先读禁用正文再说明、伪造细源出处或按名字合并来源。

优先替换冲突文字，不能在原文上再叠一层重复规则。不同来源任务、源变更和Pi原生投影机制保持。不要为自然语言再加关键词判断器、额外模型审批或全部来源确认表单。

### 5.2 只删已证重复检查

`data_tools::execute`已按原调用版本校验KnowledgeSearchInput，并在锁外调用前执行`validation?`；`source_identity::search`只有这一内部调用者，又重复校验同Schema和view。保留这一私有接缝已有的已验证输入约定，删第二份同义结构检查即可，不强行转换旧工具合同、不新造通用Validated包装层。`query.trim()`后的空串业务判断、外部工具入口、游标解码与身份绑定、当前权限/版本核验保留；不扫全仓做类型重构，不删新信任边界的校验。

准备期修复中的`claimed_epoch != lease_epoch`是本轮核对到的恒等比较：`prepare_delivery`持有会话行锁后预计算`LockedConversation.lease_epoch + 1`；`conversations/store.rs::claim_turn_in_tx`以同一不可变快照计算相同值并返回，没有第二种分配路径。第二轮Oracle核对底层后同意删除。只删调用点临时变量、不可达的比较/错误分支，保留claim操作及`.await?`、owner有效租约检查和job末尾续验；不改epoch算法，不新建分配器，也不为删除分支补测试。复用现有两条准备期回归。

### 5.3 先解决来源轨迹的资料前提，再谈通过

原轨迹允许三张表及ASR/时间定义，要求按质量规则出两版草稿。据本地只读核对，六份细来源有非实验/授权车辆业务规则，但均无`is_lab_unit`和`telemetry_consent`字段，尚未建立这两个字段的完整依据链。旧尝试曾声明schema等聚合来源，草稿出现了相关过滤；字段具体通过哪份正文或旧上下文进入模型，应优先核对已存回执和实际输入，不能从SQL字段反推已经发生某次正文读取。六份不足也不证明所有原许可资料都不足。

先按原资料建立一张短表：所需事实→实际source/revision/位置→是否在原允许集。资料取证复用工具的已有身份/定点读，不把评测参考输入Agent。外键关系仅作定位，不自动增加来源权限。

如果原范围内确实有足够依据，沿原题复验，检查实际声明和第一份正文及只改月份的继承。若不足，保留原轨迹fail/partial及具体缺口，提出“是否允许补读车辆资格结构”的单一范围决定，然后停止依赖该前提的出稿验证，其他核心链继续。原题、原允许集、原attempt和原判定始终保留；新增许可只作用于明确记录该决定之后的新尝试，不能回写原轨迹使其获得pass。若原两条消息及原资料无法满足原断言，变更验收前提必须另行明确记录，本包不预先授权。不能把无稿合理澄清改判为原出稿通过，不能删除同名旧对象、重置库或重新导入更容易通过的数据集。

SQL出现第四张表不能单独证明来源越界，也不新增SQL三表白名单；须核实际依据的SourceKey、修订和位置。声明过宽、正文越界、缺少字段依据分别判断。

现有名字多词查询已修，优先复用；若当前工具证据确实显示身份说明仍不足，再提出限定的接口改动及反例，不预建source粒度层级、标签体系、权限DSL或检索新通道。
