# 文档与生产SQL的语义整理

前置：来源同步。需求 D04/D05/D06/D07、C02/C06/C07、A05/A07/A09；职责 M02/M03/M04/M08/M10。目标合同为17.2、17.3.2、17.6及17.6.1。

## 结果与范围

长文、表格、大SQL的末尾都可被后台分批处理；陈述、例外、计算依赖、出处可回读。来源变化只影响实际依赖的内容，人工改动保持。普通问答无需等整理完或通读全文。

允许 `modules/knowledge/`、`ingestion/`、必要retrieval的确定性分块、现有预填/文档/知识影响用例、Worker、现有维护详情UI、Schema/迁移/测试。复用原模型调用与预算，不新建Agent、图服务、独立调度或通用条件DSL。

## 实现顺序与数据合同

1. M02在同一知识事务保存 `knowledge_statements`、`knowledge_relations`、`knowledge_dependencies`。陈述保留scope_text、origin、citations、supports；事实/建议/人工由真实写入路径判定，不能模型自报human。关系按已定predicate与稳定身份，私表不越owner读写。
2. M03 `source_preparations` 绑定来源修订、method_version、实际必要依赖的相关内容指纹，保存source_ranges_read/semantic_status/unresolved/进度和错误。用户文档仍由M02持有原文，不复制第二份可编辑正文。准备作业的冻结输入必须覆盖后续批次及复核实际需要的完整来源区间，不能把既有裁剪input_json当全部输入；只保留作业所需周期。成果应用同时核验来源修订、知识预期修订、相关依赖指纹、method_version和领取代次，不能只核source头；成果/有效依赖/知识索引待办同事务。
3. 分块先用段落、列表、表格行组、代码块/CTE边界；无结构按段/句。初值1200字符目标/2400单块、重叠160、可溯源背景≤256、后台每批64；无128块总上限。重复表头和背景单独标出处，不伪装原文连续区间。超embedding真实token上限继续拆。
4. 自动整理每批至多32K估算tokens、32个目标陈述，并服从实际剩余容量；未覆盖继续排作业。完整读过只证明输入覆盖，不自动标语义ready。未知映射保留原文和unresolved，不手填合成答案冒充模型成果。
5. SQL一次整理产生可复用解析事实/关系；完整CTE属于同一生产源。SQL中出现JOIN是证据，不是所有合法JOIN的白名单；跨表同名字段也不能自动等义/同编码/可等值JOIN。指标SQL示例 `computed_metrics` 明确实际输出名/表达式/口径，过滤中用到的指标只是依赖。
6. 有效层先算effective_value的实际组成，再核验其required依赖。依赖键含条目/层/purpose/目标修订与相关内容指纹；related不因曾读过就使口径失效。人工完全替换、局部替换、仅确认、同文重存分别保留真实贡献。旧自动成果无映射为unknown，不能猜无依赖。本包即接入已有v1/current_use、按ID读和新草稿校验消费者，不能只建表等v2才生效。
7. required依赖的传递关系批量读、去重、防环；A→B→S中S变化立即在current_use发现，不能等扇出队列更新B。保存内容与反向依赖同事务，既有作业分页处理大扇出，不拉长保存事务。
8. 另提供实际贡献根查询，供权限/模型端点/用户source_limits使用；包含实际贡献的related来源和个人资产来源，不能只取required。明确“只用A”时空根、unknown根、人工替换后的旧source标签不通过；A原文、无额外限制的人工知识及用户任务条件仍正常使用。
9. 内容复用与出处复用分别核验。稳定字段ID/条目路径或可证明唯一范围的映射才更新定位，正常版本事务保存新citation；重复段落不做首匹配猜测。无法可靠定位则重整；原文仍可定点读。内嵌完整条件的内容交付与出处可回读性分开判断。
10. 保存当前原文原子登记raw索引和语义准备；M02公共index job区分目标kind/revision/index version，M04仅记录投影进度。保存派生陈述只登记knowledge索引，不推进原文修订、不反触发原文重整。新目标仅由认识其kind/schema的消费者领取；消费者尚未就绪时保持真实pending，旧消费者不得误领、标完成或耗尽重试。沿既有队列的目标判别/领取过滤实现，后包按原身份接续，旧作业继续正常推进。索引配置变更复用整理成果，不再调语义模型。

本包实现并在专用实例验证current内容与版本元数据的新写入路径，但暂保必要旧兼容写入；停止为新公共修订永久复制全文的实际切换移到08。届时必须已完成04历史用途、06旧回执、07输出恢复及准备冻结输入的消费者迁移。旧knowledge_versions及所有任务/查询/资产/账本保持。旧全文缺失明确stale/not_available，不能以当前正文冒充旧版。

## 正反例与验证

| 反例 | 断言 |
| --- | --- |
| 一文关联三表，三段分别解释不同字段 | 关联只是候选；陈述/片段范围只绑定实际支持的对象 |
| 第129块后有定义；开头定义、末尾例外 | 后台覆盖末尾；支持定位包含远处例外；不能截头后ready |
| 人工四种编辑方式后来源变化 | 真正替换的有效值不被废弃建议阻断；未替换部分和同文确认保留来源 |
| A→B→S，S变而B后台未处理 | current_use及时发现；unknown链不当空链；环不会无限展开 |
| 仅负责人变化、仅索引重建、method_version升级 | 前两者不重整；最后者明确重整；依赖相关内容未变可复用 |
| 前文插入、后文重复片段 | 可靠位置才重绑定；不靠首个字符串匹配指错出处 |
| 独立人工/旧标签/空来源在“只用A”下 | 拒绝伪装成A；A自身原文及用户条件不误伤 |
| 整理pending/failed，raw待办可执行 | 两作业互不等待；页面/工具状态不互相冒充完成 |
