## 结果与允许范围

空语义库能同步完整表/字段/负责人及一份生产SQL。维护者发起后立即取得批次，后台分批保存、恢复和报告进度；后续同内容复用，完整成功才退休缺席对象和应用整批负责人。

修改 `modules/ingestion/`、必要knowledge/access/jobs公开入口，`use_cases/catalog_import.rs`、`knowledge_sources.rs`，API/Worker、现有知识管理同步UI、平台mock适配、同源Schema/迁移/相关测试。新物理表在所属私有store内访问。不要加平台SQL执行、定时任务、多生产者或逐资料失败状态体系。

## 实现步骤

1. 定义 `SourceKey`、`SourceCitation`、`SourceLocator`，保持 `EvidenceRef`知识引用原义。locator统一Unicode code point；测试emoji、组合字符、中文、换行和Rust字节/JS UTF-16边界。修订不符返回stale_source，不能用旧offset切新正文。
2. 扩展当前来源存储：`source_heads`＋`source_current`，外部唯一键含space/adapter/kind/namespace/external_id。迁移保留既有source/object身份，分批回填当前正文与比较版本；平台观测/负责人元数据与内容修订分开。旧历史不删。
3. 沿 `CatalogTable.node`保存单表一份完整生产SQL。词法归一仅忽略无意义词间排版；字符串、标识符、token边界、大小写、hint和注释文字参与相应指纹。方言不支持/词法失败按原文比较并记未解析，不证明SQL等价。纯排版保持已存正文、修订与位置。比较方法升级时，用同一新方法比较保留正文与新输入，不能拿新旧算法hash不同当业务变化；回填与实时写竞争须核验当前头，旧回填不能覆盖新内容。
4. 替换40,000字符/200字段/100页硬门槛：按完整来源JSON实际UTF-8字节，单来源8MiB、页16MiB初值，按完整对象分页。Schema、HTTP接收、代理链、适配器、MySQL字段及实际包大小限制同时核对；超限明确失败且不截断推进该对象修订。别把原文上限当聊天输入额度。
5. 同一路径 `POST /source-syncs` 幂等登记批次/作业后返回202及 `sync_id/status/status_url`；新增GET进度。新命令重传同一批次，旧已成功命令返回原回执、不补建作业。Web同批改为看后台进度，区分同步、准备、raw索引、知识索引。
6. M03保存同步业务状态/权威范围/采集基线/游标；M10只管租约代次。每页锁外读、短事务保存：来源内容＋待办＋游标＋`(sync_id, source_id)`成员。成员含unchanged、接受修订、保留子对象、待生效负责人。移除完成逻辑对内存seen/imported/maintainers的依赖。
7. 最终页保存及冲突收口后，从持久成员组合owner接口，按scope generation原子完成负责人、权威退休和终态。单对象CAS不能代替整范围代次。CAS失败重读该对象后收口或明确failed，不能跳过宣布完成。
8. 临时重领沿原sync_id/游标/命令；终态failed原命令只回失败。明确重新同步才新建批次。后页失败保留前页内容和raw待办，不应用整批归属、不推断删除。completed与failed均解除整理对目录终态的等待，整理只用已提交有效内容。

原文保存时登记raw索引与整理两类目标明确的现有待办；后续处理器在03/05深化。该包不得把未就绪队列写成ready，不能无消费者却宣称已可语义搜索。准备结果缺失但内容未变，仍保留补准备的路径。新目标仅由认识其kind/schema的消费者领取；消费者尚未就绪时保持真实pending，旧消费者不得误领、标完成或耗尽重试。沿既有队列的目标判别/领取过滤实现，后包按原身份接续，旧作业继续正常推进。

## 验收反例

- 首次空库、重复、并发同步：每稳定键只一份对象；相同external_id不同namespace不混；改名保留身份。
- 第一页A未变但负责人变化，提交后退出，第二页恢复：A及子对象不误退休；只有完整成功应用新负责人。后页failed不应用。
- 旧同步晚于新同步完成：不能退休新批新增对象或回退新来源头。最后页读取结束但CAS失败仍非completed。
- 201字段、101页、超过40,000字符完整SQL均可传输；8MiB边界按中文实际字节；过大对象无截断成功、无伪完整目录。
- SQL仅词间空白：正文/修订/位置/整理调用数不变；字符串空白、hint、解释性注释变化分别被识别。负责人变化独立生效。
- 重传已提交页不重复排待办；失败批次重传同原结果；新同步复用前批已保存内容。
- 普通维护者/无权者/超级维护者沿现有规则；后台进度不透露其他空间资料。
