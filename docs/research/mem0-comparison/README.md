# Mem0 对比执行包

准备日期：2026-10-05。供另一个 coding agent 实现并执行。**当前只完成执行包，没有安装 Mem0、生成向量或运行对比。** 实时状态只维护在 [`docs/CURRENT.md`](../../CURRENT.md)，本文件是实验约定。

## 1. 接手后先做什么

1. 从项目唯一根目录阅读 `AGENTS.md`、`docs/CURRENT.md` 的最新任务和本文件；保留已完成的 I2-MVP。
2. 核对工作树。准备时位于 `codex/semantic-maintenance-prototype`，仓库没有提交，源码均为未跟踪文件。不能用 reset、clean、切换到空工作树等方式清理这些文件；接手时重新查看实际状态。
3. **先确认向量模型选择。** 用户明确要求需要向量模型时停下来询问。前轮已给选择题，但没有明确收到 A/B 答案；“把对比做成执行包”只授权准备交接材料，不当作选择 A。
4. 模型未明确前，可以读取材料、核对依赖与固定样例，不安装/初始化向量模型、不建向量索引、不执行依赖模型的对比。若当前会话已有用户后续明确选择，沿用，不重复询问。

待确认问题只有这一项：

> Mem0 检索需要向量模型。这轮用哪种？
> A（推荐）：复用项目已有本地 `intfloat/multilingual-e5-small`（384 维），先比较记忆检索效果。
> B：使用用户指定模型；请用户提供模型名称或服务信息。

推荐 A 的原因是减少变量与外部调用费用。已有文件存在且大小匹配清单；这只证明文件可用候选，不能替代哈希核验或 Mem0 兼容性试验。[模型清单](../../../infra/embedding-model.json)固定版本为 `614241f622f53c4eeff9890bdc4f31cfecc418b3`。不要自动使用 Mem0 默认的 OpenAI 嵌入模型；DeepSeek 生成模型与向量模型是不同配置。

## 2. 本轮要回答的问题与范围

**同一批中文个人纠错，Mem0 的检索效果是否值得增加依赖和维护成本？**

本轮完成独立、可复现的离线检索比较：

- 使用真实 Mem0 OSS 库及真实向量，不用 mock 结果代替。
- 首轮使用 `infer=False`，比较已经整理好的记忆如何被找到。
- 覆盖检索相关性、用户/空间边界、版本/停用后的候选过滤、来源与未核实标记保留。
- 记录耗时、资源和实际网络/模型调用，给出是否值得进入后续验证的建议。

本轮不做公共口径修改、MVP 接入、页面改造、生产迁移、Hindsight 对比、S01/B08/P01/P02 修复或通用评测平台。也不比较自动记忆提取、冲突归纳及 Agent 最终采用行为；报告必须保留这些未验证项。后续若要比较提取或完整 Agent 流程，应另定小样与范围。

## 3. 固定的三个比较组

| 组 | 实际实现 | 用于判断什么 |
| --- | --- | --- |
| `current_lexical` | 调用当前 Rust `retrieval::asset_directory`，不手写“相似版本”替代 | 当前个人记忆检索基线 |
| `vector_only` | 同一获准向量模型 + 同一 Milvus 实例的独立集合，普通向量相似度检索 | 单独加入向量模型带来的收益 |
| `mem0` | 固定版本 Mem0 OSS，`infer=False`，同一模型与 Milvus 实例的另一独立集合 | Mem0 在普通向量之外的检索收益 |

三个组必须使用相同的语料、问题、宿主身份、当前有效状态、嵌入文本和结果长度限制。向量组 B/C 使用同一模型快照、分词、前缀、池化与归一化方式。公共知识的现有向量检索不是当前个人记忆基线，不要混用标签。

Mem0 可能带关键词、实体索引等额外能力；保持锁定版本的正常检索算法，逐项记录实际启用项、降级及默认值。不能偷偷改成只调用向量库却仍声称在测 Mem0，也不能把托管版能力写成 OSS 能力。

### 参数与运行次数

- 每次最多取 20 个原始候选，经过统一有效性检查后最多保留 5 个。
- 32 个查询，按固定顺序每组运行 3 轮；正式检索共 `32 × 3 × 3 = 288` 次。重复用于观察延迟和不稳定性，不能视为 96 个独立业务问题。
- 每组正式计时前最多 4 次预热查询；预检另用一个固定小样核对真实写入、检索与范围过滤。
- 本轮不启用额外 LLM 重排、自动提取、自动归纳或生成回答，**生成模型与收费嵌入 API 请求数均应为 0，除非用户选择了外部向量服务**。选择外部服务后，要记录实际用量并沿用该项授权；不能默默套用本地零 API 费用。
- 不根据测量题调阈值、prompt、语料或检索参数。可用不同于正式题的预检样例确认接口能运行，正式参数随后冻结。
- 超时与错误记录为错误；失败请求最多一次有依据的重试，计入实际调用和耗时。首轮代表样例不通时先定位，不直接运行整批。

为避免不同引擎分数含义不同，本轮以固定候选数量比较。尽可能关闭可选分数阈值；API 无法关闭的，记录其固定默认值与影响，不声称分数可以横向比较。负例的无关候选反映检索噪声，不能直接算作模型已经错误采用。

### 如何解释状态快照

- `current` 使用 `include_versions` 列出的索引输入；默认正式版本为1、状态为enabled。
- `channel_revised` 的索引刻意保留渠道偏好1/2版，正式版本为2。
- `channel_disabled`、`channel_deleted` 继承初始索引，仅改变宿主中的资产状态，模拟异步索引尚未清理。
- `knowledge_revised` 继承初始索引，把所引用正式知识版本从3改为4，模拟旧记忆依赖失效。
- 带 `base` 的快照先完整继承父快照，再按字段应用覆盖；`knowledge_versions` 按对象键合并。复合资产键使用 owner、space、asset ID，不能仅靠名称或正文去重。
- 各快照彼此独立，不能让上一组查询改变下一组数据。索引状态与正式状态分别记录。

语料文件中的 `asset_id` 是便于核对的逻辑标识。实际适配时用固定命名空间的 UUIDv5 等方式转换为稳定、不含语义的运行 ID，三组共享映射，评分时还原。这样不让描述性 ID 影响现有基线按 ID 排序的结果。

## 6. 必须守住的实验规则

### 同一输入，清楚区分引擎与宿主

用于嵌入的文本固定为 `name + 换行 + body + 换行 + scope`。不加入期望答案、query ID、group ID或评分类别；权限、版本等作为检索元数据。三组读到相同的业务文字，不单独给 Mem0 增加解释。

关键词基线按正式当前资产读取。两个向量组按快照对应的索引读取，模拟陈旧索引时仍经过统一回源检查。宿主检查只使用身份、正式版本、状态和依赖，**不能偷看 expected-results 决定哪条记忆“适用”**。自然语言范围是否与问题匹配由相关性评分体现，不写针对这32道题的业务关键字分支。

Mem0 的原始结果与回源后的结果分别报告。宿主过滤挡住了旧版本，不能说成 Mem0 自己理解了失效规则。

有效候选按资产ID与版本从本轮正式记录快照补齐正文、范围、来源和验证标记；不要把引擎返回的自由文本当作新的正式记录。该步骤读取源语料与状态，不读取评分答案。本轮使用本地合成快照模拟宿主回源，不宣称重新验证了MySQL事务或真实平台权限。

### 用户、空间与过期信息

- 查找前就向引擎传入宿主绑定的用户/空间过滤条件；不能全库搜完才假装实现了隔离。
- 若版本只原生支持一个 user ID，将用户与空间映射为无歧义的组合标识，并保留原始归属元数据。若所用后端不支持所需过滤，报告不兼容；不能默默忽略条件。
- 其他用户或空间的记录不得进入原始候选；旧版、停用、删除与依赖失效记录可以出现在刻意陈旧的原始索引，但不得进入最终有效上下文。
- 来源、版本与 `verified=false` 必须原样保留。模型归纳与相似度不授予公共口径地位。

### 模型、网络与费用

- 未收到明确模型选择就停在依赖决策处；不能以已存在本地模型为由跳过用户要求。
- 获准复用本地模型后，先核验已有文件SHA256，固定同一快照；禁止静默下载替代模型、调用默认OpenAI接口或自动切换模型。
- Mem0 的 `infer=False` 路径也要检查有没有隐藏调用。生成模型接口设为调用即明确失败，并记录调用尝试；可使用范围明确的禁用适配，不得模拟嵌入或检索结果。初始化需要额外依赖或网络时先查清用途。
- 关闭所选版本可关闭的遥测，记录出网目的地。依赖下载和模型推理分别记账；不要读不需要的 `.env`，不打印凭据。
- 本地嵌入 API 账单为零，不等于计算免费：报告总时间、CPU/RSS、磁盘占用及维护依赖；测不到的项标记未测量，不写0。

### 索引与清理

使用 `mem0_compare_<run-id>_...` 独立集合；原有产品集合不可改。把引擎自动创建的附属集合、历史库和本地文件也写入本次资源清单。只清理清单确认属于本次的资源，不调用无范围的reset，不使用通配删除。共享 Milvus 不可承载额外试验时报告具体限制，不重新部署产品服务。

## 7. 评分与报告格式

### 必须分别报告

1. **正例 Recall@5**：每题在有效前5条找到的相关记忆数 / 该题期望相关记忆数，再按题平均。组合题有两条答案，不能只命中一条就算整题成功。
2. **MRR@5**：首个相关记忆的倒数排名，未命中为0；只在正例上计算。
3. **负例候选噪声**：没有相关记忆的题中，仍出现有效候选的比例与样例。它表示需要下游判断，不能叫“错误采用率”。
4. **边界违规**：跨用户/空间的原始暴露，或失效记录进入最终上下文。明确列出每次违规，不能用总平均掩盖。
5. **元数据完整性**：资产、版本、来源、范围、未核实标记是否保留。
6. **成本与延迟**：首次建索引、模型首次加载、预热后查询p50/p95、实际LLM/嵌入API调用、CPU/RSS/磁盘。分清检索耗时与宿主过滤耗时。

超时、失败、缺回执不计作负例正确拒绝；报告已完成/失败/未执行数。不要剔除最慢查询，不把3次重复作为独立语义样本。报告分组的改善、持平和退步案例，保留所有原始结果。

### 必须交付的产物

```text
.local/mem0-comparison/<run-id>/
  run-manifest.json       # 输入/源码/依赖/模型指纹，用户模型决定，固定参数
  owned-resources.json    # 本次索引、历史库、文件的明确清单
  search-results.jsonl    # 每组每题每轮的原始与有效候选，错误、耗时与计数
  result.json             # 完整性、分组指标、违规、费用与限制
  execution.log           # 完整命令输出，不含凭据

docs/research/mem0-comparison-results.md  # 简洁结论及证据路径
```

报告回答：Mem0相对现有关键词检索提升了什么；相对普通向量检索还剩多少额外收益；有什么退步；增加哪些依赖与资源；哪些能力未测试。不得将本轮召回率改写成原MVP的75%准确率，不外推到千表或真实业务。

可得出的结论有三种：值得进入后续小样、现阶段优先复用现有向量能力、证据不足/不适配。**实验如实完成不要求 Mem0 胜出，也不要求达到100%。** 发现边界违规时可以完成失败报告，但不能推荐接入。

## 8. 实施与验证顺序

1. 记录用户模型选择；检查本包指纹与当前 MVP 收据。
2. 锁定真实可安装的 Mem0 和相关依赖，在独立实验目录完成一个代表样例。确认没有默认模型调用、过滤没被忽略、ID与版本可以回源。
3. 实现三组薄适配与评分；先用手工构造的候选回执验证评分公式、漏题/重复题、错误回执、旧版与跨用户拒绝。不要用真实检索输出来定义答案。
4. 冻结配置、代码、语料与答案，再完成既定288次正式检索。数据操作串行安排，不与现有数据库集成测试争用服务。
5. 保存完整结果，分析同一问题在三组中的差异，更新 CURRENT。异常保留原始证据，不能修改输入后接着拼成一轮。
6. 由未实现相应代码的审查者核对样例、原始结果、统计与结论范围；不能仅复述实现者总结。没有独立复核时明确记录未复核，不伪造审查。
