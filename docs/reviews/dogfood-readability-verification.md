| 问题 | 改动 | 验证要点 |
| --- | --- | --- |
| 模型目测结果导致计数错误 | 查询模块在授权结果读取后计算行数、空值、去重、重复值次数和数值正零负计数，交给原 Pi 结果工具 | 14 行、12 个订单；O1001/O1013 各 2 行；支付为正 12 行、为零 2 行；分页与截断不冒充全量 |

| 语义目录过于零散 | 管理目录默认按表、指标、整篇文档、术语组织；字段及关联从表内进入，仍可明确单独查找 | 服务端先筛选再分页；同名不同来源保留；负责人范围、字段编辑与后页地址恢复保持 |

| 最近对话标题过长 | 展示取首句并限制长度，原消息及完整标题保留 | 窄屏不撑宽页面，悬停仍能查看完整标题 |

## 真实 Flash 试用

沿用原本地配置、用户、数据库和会话；模型为 DeepSeek Flash，关闭思考，平台为可执行合成 SQLite 数据。使用 Carol 身份在同一会话发送 5 条用户消息，完成先给 SQL、补充订单状态后执行、继续核对已有结果；另有执行完成后的自动续接，不将用户消息数等同于模型 API 请求数。没有给模型提供验收答案，也没有重新创建查询来纠正统计。

- 初次增加基础统计后，模型给出的 14/12/12/2 正确，但解释重复订单时仍遗漏 O1001。保留原失败回复，随后在同一统计接口补充重复值及次数，测试增加独立预期。
- 修复后继续原会话、读取原结果，模型正确列出 O1001、O1013 各 2 行，其余 10 个订单各 1 行；14 行、12 单、12 行正支付、2 行零支付均与独立 SQL 一致。
- 最后一条归纳回复保留正确数字，并且没有再展示 `statistics`、`scope`、`distinct_count`、`repeated_values` 等接口字段名。截图与原文分别为 `real-flash-final.png`、`real-flash-final.txt`，旧回复保留原样。
- 查询记录仍为一份被修订草稿和一份成功执行查询。追问没有额外执行；结果卡保留 10 行预览。
- 从真实导出接口取得的 14 行 CSV 与独立 SQLite 查询逐行相符。浏览器下载等待因控制工具超时未取得路径，因此本轮不把该等待记为下载 UI 通过；原下载按钮的浏览器回归另有覆盖。
- Carol 的实际“我负责的对象”目录、表内字段及编辑入口、整篇文档与已处理纠错卡已在本地页面核对。

本地证据在 `.local/dogfood-repairs/`：`real-flash-verification.json`、`real-independent-reference.json`、`real-flash-results.json`、`real-flash-orders.csv`、`real-flash-final.png`、`maintained-directory.png`、`semantic-directory-live.png`、`correction-diff.png`。最终目录、字段编辑、纠错差异和真实回复截图均已实际查看；原始页面记录和失败回合均留在忽略目录中。本地 Web、API、Pi、合成平台与 Mem0 服务健康检查均返回 200，用户可继续试用。

## 测试修正与限制

- 首轮接口测试误设超出现有限制的租约，修正测试配置后通过；未改变产品上限或预期。新分页测试改从工作台打开目标地址并等待目录加载，避免将同页片段跳转与未刷新目录混成直接进入场景。详见 CURRENT 的“本轮验收与要求变更”。

- 真实试用只是一个合成场景的持续会话，不能推导整体准确率或保证所有自然语言解释正确。
- 没有重新验收整个 MVP、真实 Datasight、千表规模或 Mem0 召回效果；本轮未实施同步更新。
- Web 构建通过，仍有主脚本体积超过 500 kB 的分块提示；本轮没有扩展为打包优化。
