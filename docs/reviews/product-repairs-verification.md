# 产品审计通用修复与验证

日期：2026-10-11。当前状态以 `docs/CURRENT.md` 为准。

## 修复范围

本轮处理产品审计中有明确证据的六类问题，不修改现有 mock 业务资料、模型选择或 Mem0 策略；来源同步及缓冲区继续暂停。

| 问题 | 通用修复 | 主要验证 |
| --- | --- | --- |
| 回执丢失后产生新消息身份 | 提交前持久保存创建ID、消息ID、正文和模型选择；同ID重试，新草稿独立保留。按服务端用户/空间隔离；已知无提交拒绝可修改后再发；目标已不可访问时结束待确认并保留原草稿 | 创建和消息真正提交后丢回执；同页/刷新重试；两账号、空间夹具、旧草稿迁移；超长输入、模型配置撤下；原会话被删除 |
| 空闲页面高频请求 | 工作台无变化逐步退避，隐藏暂停、回来或聚焦重查；空增量复用历史对象。Skill按状态变化及低频核对 | 60秒完整空闲请求采样、隐藏/恢复、两个后台查询、独立取消、完成通知和草稿 |
| 来源与维护状态不清 | 来源资料、模型整理、人工维护、来源变化待复核使用同一展示规则，文档仍整体呈现 | 四状态展示；真实人工保存回读；不将人工维护表述为业务验证 |
| 选了Skill不能仅在本会话移除 | 选择身份和稳定移除操作；待处理/恢复输入及有效运行租约期间拒绝变化，已结束失败不永久阻塞；独立后台SQL不受影响 | 重放、重选、并发、跨用户/空间、公共Skill、已删资产、Pi旧压缩上下文和原生读取、晚到列表、已应用输入后预算耗尽 |
| 长文命中位置丢失 | 向量保留定位，经授权回源后从正式正文构造片段。旧索引用既有片段键定位，无需重建 | 设备和图书馆两类长文、Unicode、多个条目、同名干扰、未知位置、旧版/停用/来源失效/跨空间 |
| 每个输出片段重读全部旧正文 | Pi增量做50毫秒或约2048字符合并，消息边界独立；追加查末序号，重放查对应正文 | 100/1000增量、持续刷新、Unicode、消息边界、实际数据库1000片段、幂等/缺口/最终正文及Pi进程恢复 |

检索排序另预计算每个对象的词法分数和两通道排名，保留原精确名称、并列排序和类型覆盖。没有新增Agent循环、规划器、压缩器或数据库服务。

## 本地测量

- 原空闲样本31.875秒139次API请求，折合约261.65次/分钟；审查修复后的专项样本完整60.010秒12次GET，计入工作台、角色和Skill。不同样本仅支持当前空闲请求频率改善，不代表生产容量或所有页面性能。
- 隐藏5秒没有新请求；恢复可见10毫秒内发起核对。该次活动snapshot间隔736、742、723毫秒；查询完成293毫秒后显示结果。页面可见性使用浏览器事件夹具，非操作系统后台调度测试。统一验收重跑的具体数值由其收据与本地报告保存，不要求每次计时相同。
- 同步到达的100/1000个文字delta各合并为一次传输；持续流每50毫秒交付缓冲。数据库专项直接追加100/1000片段耗时约2.4/21.5秒，正文和事件一致。该耗时是本机一次测量，不作为性能SLA。正常追加从查询全部旧片段改为主键前缀倒序读取一行，最终提交仍完整校验。
- 当前没有新的端到端模型准确率数字。本轮证明相关段落正确交付，不能直接推导SQL或解释整体准确率提高了多少。

## 发现后修正的问题

- Skill移除成功后，先发出的旧GET可能恢复已移除项。浏览器故障注入先复现，再通过响应代次与合并刷新修复；前后日志分别为 `skill-removal-stale-list-before.log` 与 `skill-removal-stale-list-after.log`。
- 待确认消息不能无限重试已知被拒的冻结载荷。提交前使用同源契约检查；服务端明确 `invalid_input` 表示本次未提交时解除待确认状态，原草稿仍保留。网络或无法解码的回执继续保持原身份。
- 独立审查发现待确认消息所属对话删除后，会阻止所有后续发送。明确收到 `not_available` 后仅结束该消息的本地待确认记录，说明无法继续核对是否保存，原草稿只读保留；不自动转发到新对话或覆盖新草稿。页面删除和后台删除都已在真实保存后丢回执场景验证；修前失败保留在 `.local/product-repairs/conversation-deleted-target-reproduction.log`。
- 独立审查还发现，已应用输入因交付耗尽进入终态 failed 后不能撤回，原 Skill 检查会一直阻止选用与移除。改用 M05 只读 pending 判断并保留有效运行租约检查；其他流程的 pending_ids 含义不变。通过真实预算预留/结算耗尽与 Worker 四次失败复现：可恢复阶段仍阻止，输入与工作终态后允许移除，新输入不再携带旧 Skill 的 Pi 压缩检查点，原任务、工具身份和预算记录不变。修前证据为 `.local/product-repairs/skill-terminal-failure-repro.log`，修后7组专项通过。全部模型响应来自本地协议替身，没有商业模型调用。
- 首次统一验收发现上述测试的1500毫秒租约过短：一次恢复在进入预算检查前已失去租约，严格耗尽计数失败。诊断区分 `lease_lost` 与 `budget_exhausted`，记录当时同一运行和租约代次、已过期223毫秒。专项改用产品默认15000毫秒与相应等待上限，仍要求四次预算耗尽，并断言没有其他交付错误；不修改产品代码或放宽业务断言。7组专项已重新通过。原失败收据与诊断分别保留 `.local/product-repairs/unified-first-failure.json`、`skill-terminal-diagnostic-failure-report.json`；最终统一结果见 CURRENT。
- 增加服务端空间字段后，启动器登录自检同步核对空间；没有撤回此前的Carol账号支持。
- 旧runtime测试要求已取消的“已保存的任务”和原始任务ID显示。按已确认的聊天界面改为问题可见与数据库持久结果双重断言，保留失败日志与全部恢复断言。详见CURRENT的验收变更。
