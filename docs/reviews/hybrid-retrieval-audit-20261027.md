## 四条复杂度要求如何落地

1. **不为低概率问题堆保护。** 本报告没有可用发生率数据，概率均未知。排序丢位置、分片覆盖和尝试清零由普通确定输入触发；已有异步修订核验属于业务合同。没有据此新增罕见竞态框架、保活服务或大规模状态机。新提出的低概率保护先给触发证据和代价，由用户决定。
2. **同一外部输入只在对应边界校验一次。** 下一包沿当前链改为类型化输入，不全仓重构。前后两次HTTP请求是两个边界；等待索引/网络后重核版本是新时间点，不能误删。
3. **不提前抽象。** 迁接的一次性来源转换已内联；owner窄读取是既有存储职责，不是新文档服务。不预建trait工厂、万能预算器、检索会话或策略层。
4. **直接传播不能恢复的错误。** 删除把普通故障解释成成功/失效的分支，复用现有有限重试。保留能区分明确失效与服务故障的必要match，不按行数强拆函数。
