现有测试明确要求旧 thinking 消失、`reasoning_content=''`，测试通过只证明实现达到了这个预设。S08 同时改了投影、兼容字段、控制回执和 system 规则，一次成功不能证明删除 thinking 是必要条件，也不能把旧失败唯一归因于 stale thinking。

## 语义维护仍未开放，解除条件需要收敛

真实预填继续 `--prefill disabled`。`prefill/input_tokens.rs` 的公开 tokenizer 与模板计数，是本地分片/准备的依据；它不是托管 API 计费的无条件上界。只修改变量名和说明，不能把关闭的功能算作可用。

本地与 Oracle 一致认为，不应把“证明供应商内部模板逐 token 相同”变成无限期前置。沿现有能力解决即可：核对适用服务端输入容量、输出上限和最高适用单价，用有依据的上限完成显式收费试用的预留；公开 BPE 用于现有分片估算，实际 usage 用于原账本结算，未知回执仍保留原身份。不能为了减少预留擅自降低用户所需上下文，也不能以估算值冒充已证硬上界。若没有适用依据，保持该收费通道关闭并明确具体缺什么，手工语义维护和无外发验证可独立继续。

在有效授权下，用一条合成资料的新增/变更、整理、索引更新、检索回源闭环确认实际维护可用。无需新建 token 服务、模板框架或改数据库/SDK；Rust 单次结构化建议调用本身不构成第二个 Agent 循环。
