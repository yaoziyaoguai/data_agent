# 正式页面体验优化：视觉复核

日期：2026-10-10。对应增量 `I2-EXPERIENCE-OPTIMIZATION`。

## 方向与检查范围

沿用用户确认的 `prototype/experience-preview/preview.html`：工作台以对话和结果为主，语义管理供维护者查阅与编辑，个人积累以列表、搜索和可修改模板为主。正式页面继续使用现有 React 组件与业务接口。

独立视觉审查者 `/root/experience_visual_check` 查看工作台、语义、资产与文档编辑的8张实际截图，未阅读实现代码。属于已有界面优化，一轮评审，不打分。主代理随后核对修正后的截图，并在本地正式服务实际操作文档预览、取消/继续编辑、模板采用和手机导航。交互结论另由浏览器回归证明。

## 发现与处理

| 发现 | 处理与证据 |
| --- | --- |
| 桌面语义截图仍是页面切换首帧，旧导航高亮与加载状态混在一起 | 等到对象、字段和当前导航就绪再截图；正式服务的 `aria-current` 与实际高亮一致。见 `docs/images/semantic-management.png`。 |
| 手机目录字体偏小，当前对象滚出可见范围 | 目录最小字号调整到12px，选择/尺寸变化后滚动当前项到可见区。见 `.local/experience-optimization/semantics-mobile.png`。 |
| 空态创建按钮、个人归属说明、工作台标语重复 | 保留顶部创建入口，删除重复操作及说明；对象名称、状态、负责人、依据与主要动作继续保留。 |
| 单行结果中两个金额列同样突出，业务单位缺少中文说明 | 当前结果契约没有可信业务标签与单位，不按字段名猜测后改写数据。保留原字段和数值；没有分类时禁用图表。可靠指标标签作为后续契约工作，不扩大本次改版。 |

## 修正后观察

- 1280×720桌面：左侧账户可见；工作台输入工具栏紧凑；结果在SQL之前；语义字段采用紧凑行；资产列表将完整内容和次要操作折叠。
- 390×720、320×568窄屏及390×320短屏：导航进入抽屉，输入与发送可达；文档编辑底部保存操作可见，表格按自身宽度滚动。
- 整篇文档的目录、编辑/阅读预览和离开保护均有实际交互记录。模板采用后收起模板列表，可继续修改正文。
- 主代理复用现有截图与独立意见完成一轮修正，没有新增视觉方向或再次派发评分。
