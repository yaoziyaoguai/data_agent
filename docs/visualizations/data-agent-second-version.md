第二版把语义、查询结果和分析成果连接得更紧。你能核对计算规则、追问结论的依据，并把报告或方法留给下次。

## A 先说清第一版的起点

第一版已经能找表、解释口径、生成 SQL 和聊天取数。它已有共享语义、个人记忆、Skill 和权限规则。

| 第一版已有的能力 | 用户原来就可以做什么 |
| --- | --- |
| 语义录入与预填 | 保存表、字段、指标 SQL、关联及长文档；人工修改单独保留 |
| 搜索和补读 | 结合名称、关键词和向量找资料，再核对来源与版本 |
| 长期对话与后台查询 | 补充条件、多任务续聊、并行查询、单独停止、预览和下载 |
| 个人记忆与 Skill | 使用 Mem0 积累个人经验；明确选用个人或公共 Pi Skill |
| 澄清与角色权限 | 缺信息时提问；由对象负责人维护正式口径 |

这次继续使用 Rust、Pi SDK、MySQL、Mem0 和 Qwen / Milvus。下面重点讲新能力，以及原有能力加强在哪里。

比较起点是第二版实施前的代码 `6801df7`。它包含第一版上线后的协作和交互修复。

## B 七项变化，一眼看懂

| 能力 | 第一版已有 | 第二版的具体变化 |
| --- | --- | --- |
| 来源与预填 | 来源、模型建议、人工修改分层 | 修复漏血缘与资料混版；补齐文档关联；加强人工值保护 |
| 计算口径 | 文字、指标 SQL、粒度和关联说明 | 增加能检查的结构规则；提示重复累计、时间及单位风险 |
| 检索 | 名称、关键词、向量和分页 | 按对象种类、相关对象、明确业务域缩窄范围；返回补读位置 |
| 主动澄清 | 已有提问、条件合并与续接 | 明确先查资料；澄清必须有实际问题；补强回答、换题和恢复验证 |
| 分析依据 | 已有多条查询和结果读取 | 保存结论、计算说明、条件与来源；登记的数字核对结果单元格 |
| 分析报告 | 已有前 10 行预览、图表和 CSV | 新增本人任务报告；绑定依据与聚合图表；保存后可重开、续改 |
| 经验复用 | 已有 Mem0、Skill 和纠错建议 | 新增公共查询案例、私人方法待确认草稿，以及直接引用的维护提示 |

主动澄清这项以补强为主。报告、正式查询案例和方法草稿属于新增能力。

## C 语义构建：让口径能参与计算

语义可以理解成数据的使用说明。第二版在说明旁增加计算规则，方便 Agent 读取和系统核对。

```tree list
语义记录 | 三类内容分别保留
  来源事实 | 平台元数据、DDL、加工 SQL、文档
  模型建议 | 推断、引用依据和未确定的缺口
  人工修改 | 负责人核对与编辑后的内容
```

```flow TB
[当前有效正文与计算规则] -> [Pi 按规则生成 SQL]
[Pi 按规则生成 SQL] -> [Rust 提供业务诊断]
```

来源事实、模型建议和人工修改仍分别保存。人工修改后，重新预填会保留人工值。

引用存在可以证明可追溯，不能证明推断正确。关键口径仍须核对。

| 规则 | 用合成净收入说明 |
| --- | --- |
| 每行代表什么 | 一行是一个订单商品行，金额已经分摊到行 |
| 怎样计算 | `SUM(paid_amount_cents - refunded_amount_cents)` |
| 采用哪个时间 | 按 `paid_at` 选择付款期间 |
| 过滤及单位 | 排除测试交易与未成功付款；金额单位为分 |
| 怎样关联 | 关联客户标签可能重复订单行，须核对重复累计风险 |

如果说明和计算规则来自不同层，可能出现矛盾。因此，第二版让有效正文和规则采用同一层。

SQL 诊断会提示能可靠识别的风险。复杂 SQL 的未检查部分会明确标出。

诊断目前是非阻断提示。它不能保证口径正确，复杂计算仍由 Pi 调查和生成。

来源改版后，旧规则可作为待核对线索。系统允许继续补查，但不会把失效规则用于正式查询。

## D 检索：先找范围，再读完整依据

第一版已经有混合检索。第二版增加了更具体的范围表达，减少一次读入无关资料。

```flow TB
[用户的问题] -> [对象种类、相关对象、明确业务域]
[对象种类、相关对象、明确业务域] -> [名称、关键词、向量找候选]
[名称、关键词、向量找候选] -> [核对权限、状态和版本]
[核对权限、状态和版本] -> [相关片段与补读位置]
[相关片段与补读位置] -> [按同一版本补读正文或规则]
```

例如，问收入口径时，可以先找相关指标和业务文档。需要理解关联时，再补读涉及的表和字段。

每个对象最多返回三个相关条目。回执有大小上限，省略内容会给出补读位置。

如果当前范围没有结果，Pi 可以调整范围再查。空结果不能证明整个空间没有资料。

采用过的资料改版后，系统会检查旧上下文。如果案例引用指标，而指标使用一张表，表改版也会触发核对。压缩摘要不能继续沿用这些过期规则。

这里改进的是检索范围和材料交付。真实千表召回率、延迟和费用变化还没有新实测。

## E 跟着一个问题，看调查与澄清

用户问：为什么 2 月收入比 1 月低？

## F 分析结果：结论、数字、报告能对应起来

第一版已有查询结果与图表。第二版新增独立的分析依据记录，以及可继续修改的报告。

```flow TB
[成功查询与当前有效资料] -> [分析依据：结论、计算说明、条件、限制]
[分析依据：结论、计算说明、条件、限制] -> [本人任务报告：结论与聚合图表]
[本人任务报告：结论与聚合图表] -> [重开阅读或继续追问]
[重开阅读或继续追问] -> [核对当前条件与来源，再保存修订]
```

比如，Pi 想说某渠道对收入变化贡献较大。它可以用查询核算渠道变化，再把结论绑定到对应结果。

明确登记的数字会核对查询、列、行和单元格值。系统不扫描正文全部数字，也不自动证明业务因果。

| 第二版新增的报告能力 | 用户能看到什么 |
| --- | --- |
| 保存与重开 | 一项任务保存一份本人报告，结论与依据一起读取 |
| 继续修改 | 条件变化后核对新分析，保存新的修订 |
| 聚合图表 | 折线图、柱状图绑定已保存的聚合结果 |
| 失效处理 | 条件改变、资料失效或结果不可读时，明确显示状态 |

前 10 行预览和 CSV 下载继续保留。报告绘图读取有界的已保存结果，平台仍最多保存 1,000 行。

截断结果不能当作完整明细累计。图表也不是完整 BI 编辑器。

结果过期或读取权撤回后，报告不回放失效正文和图表。重新运行需要新的有效聊天执行授权。

## G 经验保存到哪里，下次怎么使用

Mem0 和 Pi 原生 Skill 在第一版就已接入。第二版主要补齐查询案例和从分析生成待确认方法的入口。

| 内容 | 正式保存位置 | 下次怎么找到或使用 |
| --- | --- | --- |
| 共享语义 | MySQL 的正式知识 | 语义检索找到候选，再核对权限与当前版本 |
| 个人记忆 | MySQL 的本人资产 | Mem0 提取和召回偏好、纠错候选；应用回源核验 |
| 公共查询案例〔新增〕 | 与共享语义同一知识体系 | 检索适用问题、参数、SQL、粒度与依赖，再决定沿用或改写 |
| 本人分析报告〔新增〕 | MySQL 的本人任务记录 | 从对应任务重开；Pi 可读取当前修订继续修改 |
| 分析方法草稿〔新增〕 | 本人的待确认记录 | 编辑确认后成为私人 Pi Skill，再明确选用 |

共享语义承担团队公共口径。个人记忆保存本人经验，两者的维护规则和召回入口不同。

语义与个人记忆的向量索引仍用 Qwen / Milvus。索引可以重建，正式内容以 MySQL 为准。

```flow TB
[用户要求整理本次方法] -> [私人待确认草稿]
[私人待确认草稿] -> [本人编辑并确认保存]
[本人编辑并确认保存] -> [私人 Pi Skill]
[私人 Pi Skill] -> [明确选用后供当前对话读取]
[私人 Pi Skill] --> [另行明确发布：形成公共副本]
```

待确认草稿不会进入正式资产目录、索引或已选 Skill。公开发布和选用仍是独立动作。

公共查询案例由有资格的维护者明确录入。私人聊天、结果和记忆不会自动复制进去。

来源变化时，可以查看已经登记的直接引用。比如，案例声明按某指标计算，指标改版后就需要重新核对。

提示保留旧绑定与停用项，方便核对案例和方法。

维护提示不识别所有文字里的隐含依赖。超级维护者也不能借此查看他人的私人方法。

## H 底座怎样复用，哪些结果已经验证

| 部分 | 第一版与第二版沿用的责任 |
| --- | --- |
| React | 展示、输入与交互 |
| Rust | 权限、正式知识、任务、查询、个人资产和版本状态 |
| Pi SDK | 理解、调查、澄清、工具循环、会话恢复与压缩 |
| Mem0 | 个人记忆提取与候选召回 |
| MySQL / Qwen / Milvus | 正式记录；向量表示；可重建的检索索引 |
| 数据平台适配器 | 当前用合成平台提供资料、权限和查询 |

第二版把新能力放入既有业务模块。报告归分析任务，公共案例归正式知识，私人方法归个人资产。

七个增量的本地实现与验收已完成。各项分别通过 12、10、8、9、12、10、12 组统一验收。

最后 12 组验收的代码与契约指纹一致。它覆盖权限、保存、恢复、原生 Skill、原生压缩、页面和接口。

这轮官方 DeepSeek、embedding 和 Mem0 服务请求为 0 次。真实 Flash 的预填、提问和自主分析质量仍待小样验证。

目前还没有接入真实 Datasight。同步缓冲区、公共报告分享、完整 BI 和微服务拆分保留为后续范围。
