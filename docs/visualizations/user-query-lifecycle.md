一条用户问题可以包含多个分析任务，每个任务又可以产生多份SQL。Pi根据当前资料和结果选择下一步。Rust保存任务、依据、授权和结果状态。SQL完成后，Worker把结果事件送回同一会话，Pi继续解释。

## A 用一条复杂问题展开

> 分析2026年9月的座舱语音质量。按轮次locale和ASR引擎版本，对比首次成功率、最终成功率与重试救回占比。排除实验车辆及未同意遥测的记录。同时分析相关会话的TTS失败和P95延迟。

> 核对文档、字段定义和生产SQL，并采用我已选的分析Skill。需要我选择的口径先问清。条件明确后，生成并执行只读SQL，保存含图表的报告，再把分析方法准备成私人Skill草稿。

这是合成示例，用来展示可触发的路径。日期和指标用于说明流程。

| 概念 | 在这个例子里的含义 |
| --- | --- |
| 用户问题 | 上面整条自然语言消息 |
| 分析任务 | 例如ASR质量分析、TTS质量分析，各自保存条件和版本 |
| 检索请求 | Pi为当前缺口构造的搜索词及范围 |
| SQL查询 | 某任务下的一份可执行SQL、参数和查询身份 |
| 会话 | 承载多条消息、多个任务及其历史的同一个Pi会话 |

下图按v2工具合同展开。公共检索和个人记忆的具体通道由实例配置决定。本地试用的数据平台使用合成数据执行器。

## B 从用户输入到提交查询

```sequence num
participants: 用户与页面, Rust服务, Worker, Pi, 大模型
用户与页面 -> Rust服务: 发送用户消息与会话身份
Rust服务 -> Rust服务: 核身份和重复提交，保存原文
Rust服务 -> Rust服务: 冻结模型配置，建立预算和待办
Rust服务 --> 用户与页面: 返回消息ID，持续推送事件
Worker -> Rust服务: 领取待办，建立运行并持续续租
Rust服务 --> Worker: 返回检查点、任务、权限和资料范围
note Worker, Pi: 有可用个人记忆且范围允许时，准备相关记忆
Worker -> Pi: 恢复同一会话，交付本轮输入
Pi -> 大模型: 提供历史、当前事实、工具与已选Skill目录
大模型 --> Pi: 选择任务归属和下一组工具
Pi -> Rust服务: update_analysis_task 建立或修订任务
Rust服务 --> Pi: 返回task_id、条件版本和活动范围
== 按当前缺口循环调查 ==
Pi -> Rust服务: 搜索、补读、查任务或读取已有结果
Rust服务 --> Pi: 返回实际内容、来源、版本和续读位置
Pi -> 大模型: 将工具回执交回同一会话
大模型 --> Pi: 决定继续取证、澄清或生成SQL
note 用户与页面, Pi: 需要用户决定时，先保存澄清，再等待用户续答
Pi -> Rust服务: request_query 校验并保存SQL草稿
Rust服务 --> 用户与页面: 推送SQL卡片及待确认状态
Pi -> Rust服务: 明确获准时调用execute_query
Rust服务 -> Rust服务: 绑定原话、SQL版本和条件版本，确认并排队
Rust服务 --> Pi: 返回queued及查询身份
Pi --> 用户与页面: 交付本轮说明和提交状态
```

这条示例明确要求执行。Pi可以在条件和SQL确定后提交。用户只要求解释或准备SQL时，链路停在草稿与说明交付处。

模型按问题需要选择工具。一次响应可以包含多个工具调用。工具执行回执再进入下一轮模型输入。

同一会话的Agent推进由宿主串行安排。平台查询由Worker独立跟踪。切换分析任务时，应用更新活动任务和相应资料范围。

## C 一次语义检索内部发生什么

```sequence num
participants: Pi, Rust工具, Embedding端点, Milvus, MySQL, Mem0
Pi -> Rust工具: search_knowledge 搜索当前任务所需依据
Rust工具 -> MySQL: 取得权限、来源允许集与当前修订
Rust工具 -> Rust工具: 固定本次检索范围后释放会话锁
== 公共资料召回与个人资产读取 ==
Rust工具 -> Milvus: 在允许范围内发起中文BM25召回
Rust工具 -> Embedding端点: 对本次搜索词生成向量
Embedding端点 --> Rust工具: 返回查询向量
Rust工具 -> Milvus: 在同一允许范围内发起dense召回
Milvus --> Rust工具: 返回知识条目和原文片段候选
note Rust工具, Milvus: 两路独立推进，已有候选可先回源核验
Rust工具 -> Mem0: 配置启用且范围允许时搜索本人记忆
Mem0 --> Rust工具: 返回本人记忆候选
Rust工具 -> MySQL: 读取候选当前正文、出处和必要支持
Rust工具 -> Rust工具: 融合排名，去重并补齐可交付候选
Rust工具 -> MySQL: 提交回执前重核权限、状态与修订
Rust工具 --> Pi: 返回内容、支持状态、检索覆盖及补读入口
== Pi按本题缺口继续取证 ==
Pi -> Rust工具: read_knowledge 批量读定义、结构或支持
Pi -> Rust工具: read_source 按原修订和位置读原文
Rust工具 --> Pi: 返回所请求内容与下一位置
```

BM25寻找字面匹配。dense寻找语义相近内容。RRF把两路排名合并，精确身份有优先处理。同类高相关字段可以一起返回。

公共命中包含两种内容。知识条目提供已整理的定义、条件和关系。原文片段直接指向文档或生产SQL的具体修订与位置。

命中回源后，Rust交付相关正文和已知必要条件。Pi根据缺口补读字段结构、例外或相邻段落。检索返回值同时说明内容、支持和覆盖情况。

| 回执信息 | Pi据此判断什么 |
| --- | --- |
| content_state | 本次请求的指定内容交付到哪里 |
| support_state与supports_complete | 条件和例外已交付多少，整理是否还有未知部分 |
| search_coverage | 本次各检索通道覆盖到哪里 |
| continuation / citation | 下一次从哪个修订和位置继续读取 |

本人记忆进入用户与空间隔离的资产分支。已选Skill提供目录和版本，正文与附件通过Pi原生read按需读取。

索引滞后或通道不可用时，系统按现有能力使用当前资料读取或词法路径，并在回执中表达覆盖缺口。资料范围在各召回通道及回源交付时生效。

## D SQL异步完成后，解释从这里继续

```sequence num
participants: 用户与页面, Rust服务, 查询Worker, 数据平台, Pi, 大模型
查询Worker -> Rust服务: 领取已确认的查询
Rust服务 --> 查询Worker: 返回原SQL、参数和稳定查询身份
查询Worker -> 数据平台: 通过适配器提交只读查询
数据平台 --> 查询Worker: 返回受理标识或实际状态
查询Worker -> 数据平台: 查询运行状态，必要时沿原身份查证
数据平台 --> 查询Worker: 返回成功、失败或取消结果
查询Worker -> Rust服务: 保存状态、结果引用与原任务条件
Rust服务 --> 用户与页面: 推送query_result，更新结果卡片
Rust服务 -> Rust服务: 生成绑定原查询的结果输入并排队
Rust服务 -> Pi: Worker领取后续接原Pi会话
Pi -> Rust服务: get_query 按需读取结果、统计或分页
Rust服务 --> Pi: 返回实际结果和完整性信息
Pi -> 大模型: 提供原问题、原条件与结果回执
大模型 --> Pi: 组织解释，选择需要保存的成果
Pi -> Rust服务: 按需保存evidence、报告或私人Skill草稿
Pi -> Rust服务: present_analysis_answer 绑定正文中的数值来源
Rust服务 --> Pi: 返回核验后的answer_text及完整sources
Pi -> Rust服务: 宿主调用finish_run，提交正文、引用与检查点
Rust服务 -> Rust服务: 保存正文和读取绑定，推进相应任务状态
Rust服务 --> 用户与页面: 展示正式结论、报告与图表
```

自动结果输入携带原query、任务和条件版本。Pi按实际SQL和绝对日期解释结果。恢复和结果唤醒沿用原操作与预算身份。

一份结果答案可以引用多个合法查询。答案归属和实际来源分别保存。组合交付时，每份正文保留原来源及适用范围。

数值通过结果单元格、参数或同范围统计绑定。需要额外计算的差值、比例和分组进入相应SQL。新增补算查询按其授权范围处理。

用户要求保存报告时，Pi先保存可引用的分析依据，再组合报告与图表。方法复用请求会生成私人Skill草稿，用户在个人积累中核对和保存。

## E 复杂问题可能触发的分支

| 触发条件 | 系统接下来的动作 | 用户可见结果 |
| --- | --- | --- |
| 一条消息含多个分析目标 | Pi建立或拆分任务，按目标顺序调查，必要时冻结已完成正文 | 各任务保留自己的条件、SQL与答案 |
| 指代依赖前文 | Pi结合会话历史，必要时read_analysis_task或read_conversation | 续答沿用已确定条件 |
| 口径仍有多个有效解释 | 保存独立澄清问题与ID，等用户回答后修订 | 展示待选择的问题 |
| 用户明确限定资料 | 保存来源允许集，各通道按范围召回和交付 | 依据缺口及所需范围明确可见 |
| 文档还在整理 | 采用当前可读原文片段，显示整理及支持状态 | 已有充分原文时继续分析 |
| 工具内容较长 | Rust按剩余容量交付片段和续读位置 | Pi按需要继续读取 |
| 会话接近上下文阈值 | Pi原生压缩历史，保留近期内容和持久任务事实 | 同一会话继续推进 |
| 固定输入或单项仍超过容量 | 返回明确容量状态，由当前流程处理 | 显示具体限制或失败原因 |
| 用户只改月份 | 修订对应条件版本，保留其余已确定条件 | 新草稿采用新日期 |
| 旧查询较晚完成 | 结果绑定原查询和条件，按原版本解释 | 新旧分析各自归属清楚 |
| 用户停止某条查询 | 发送取消请求，由Worker查证平台终态 | 区分取消请求和已取消 |
| 运行中断后重领 | 恢复Pi检查点和原工具身份，接回成功回执 | 已完成部分继续交付 |
| 完整正文与绑定已发布到检查点 | 直接接续原正文提交 | 具备条件时恢复无需额外模型调用 |
| 资料权限或有效性变化 | Rust核对当前许可和来源，按范围重建Pi投影 | 返回可用内容或明确失效状态 |
| 用户明确要求记住偏好 | 修改本人记忆，经Mem0及原资产流程维护 | 后续允许范围内可检索采用 |
| 用户选择发布Skill | 保存当前空间的独立公共副本 | 公共负责人按原维护规则管理 |

每条消息沿已确认的24次调用边界执行。连续临时失败达到3次时停止相应重试。Pi压缩与恢复也沿原预算和调用身份处理。

模型配置在消息接收时冻结。输入token、输出预留和请求体字节分别控制容量，Pi按该配置推导压缩阈值。

## F 聊天前，语义资料怎样准备好

```flow LR
维护者手动同步 -> 当前来源: 平台表结构与完整生产SQL
文档维护 -> 当前来源: 文档正文及表字段关联
当前来源 -> 内容比较: 稳定身份与内容指纹
内容比较 -> MySQL正式内容: 保存变化及当前修订
MySQL正式内容 -> 原文切块: 保留修订与位置
原文切块 -> Milvus公共索引: BM25与向量
MySQL正式内容 -> 后台整理: 解析SQL与文档内容
后台整理 -> 定义关系与支持: 口径、条件、例外及出处
定义关系与支持 -> MySQL正式内容: 保存成果并保护人工内容
定义关系与支持 -> Milvus公共索引: 更新知识条目投影
Milvus公共索引 -> 在线语义检索: 按本题范围召回
```

一张表关联一份完整的当前生产SQL。同步时比较内容，变化影响相应整理与索引。SQL里的字段来源、计算和关联关系形成可复用成果。在线调查可以按具体缺口补读原SQL。

文档保留完整当前正文。切块保存可定位的原文位置。整理把局部解释关联到相关表、字段、指标和条件。同一文档可以解释多个对象，同名字段需要结合表、来源与适用范围核对含义。

| 位置 | 保存的主要内容 |
| --- | --- |
| MySQL | 正式语义、当前来源、关系、出处、任务、SQL、授权、操作及结果引用 |
| Milvus公共集合 | 可重建的原文和知识检索投影 |
| Mem0及个人资产存储 | 用户与空间隔离的个人记忆，资产身份与版本由应用管理 |
| Pi会话存储 | 原生消息、工具回执、压缩与检查点条目 |
| 数据平台或合成执行器 | 业务数据查询、运行状态与结果 |

后台同步、整理和索引由对应Worker作业推进。聊天调查读取当前已准备的资料和相关原文。
