# 独立判分与证据

本目录只供操作者判分，不进入产品Agent输入。所有数字来自冻结合成规范、独立SQL和人工预期；不得从产品本次回答反写答案。

## 状态

| 状态 | 使用条件 |
| --- | --- |
| not_run | 尚未开始；模板默认 |
| pass | 当前版本/环境完成全部规定步骤和断言，证据可定位 |
| fail | 前置条件成立，实际违反已确认预期；记录实际差异和用户影响 |
| partial | 已执行部分，但剩余分支或产物没有覆盖，例如B14只出现一条查询 |
| blocked_environment | 缺角色、数据、检索模式、服务或受控fixture；写出具体缺什么 |
| blocked_authorization | 缺Pro/付费批量/隔离运维等本轮明确授权，不扩大权限 |
| inconclusive | 超时、回执未知或证据不足，尚不能判产品正确或错误 |

不得把blocked、partial或工程证据算入真实模型通过率。先报各状态计数及总数160，再按实际完整执行的同类场景分别报告；注明分母，不混不同版本、模型或平台。

## 每项最少证据

原始case_id/attempt_id、代码commit、环境配置引用、实际角色/模型/模式、执行时间、精确用户消息和步骤、task/run/query/result/report/asset与业务版本、最终SQL/参数、实际答复、证据文件、预期出处、断言逐项结论和总体理由。只写“正常”“有问题”或贴一张无上下文截图不足以pass/fail。

优先保存小而完整的本轮轨迹；不要导出用户全部历史。不记录凭据、真实业务数据或完整私密思考。对工具只摘与本项相关的参数/返回码、版本和稳定身份。

## 数字和语义分别核对

- 独立参考SQL在内存中由schema.sql、seed.sql、etl.sql建库计算；`expected-results.json`保留SQL和期望行。金额以整数分为基准，70元与7000分等价；显示单位和精度还须符合本次明确要求。
- 行数38、订单29、下单件数47是不同概念。全表含测试39行。10行预览不等于完整结果；1000行保存上限不等于59319行笛卡尔积全量。
- 订单退款率3/9与金额退款比例8000/110000不能混用；退款发生日2月7000分不能用付款归属累计退款9000分替代。命名指标不替用户消除真实歧义。
- `is_test=0`是非测试。SQL数值正确但文字说反，数字断言可通过，语义断言失败，整体不能全pass。
- 贡献是可计算差额，不自动证明业务原因；来源没有成本、商品分类、历史拉链时明确缺口，不得编造。
- 读取工具正确和模型确实采用完整依据分开看；前三保留要看首次回执，后来补检索不能洗掉首次缺陷。

## 复用、重试和问题合并

同一当前轨迹只有真的覆盖多项完整输入/断言时才能共用。记录evidence_id和每项对应步骤，不按题名相似继承通过。业务变体/工程fixture/旧样本只能作为补充。

每个失败保留原attempt；不补答案给模型后只记修正版。不无限调整提示到过关。确需重复只改变一个明确变量，说明原因、原结果和新结果。unknown按原身份查证，不能换ID绕过。

问题可以合并成一个issue，但列明全部case_id、尝试、证据和置信度。先区分产品回归、环境缺失、历史未知、模型质量和未实现范围，不靠代码阅读取代实际复现。
