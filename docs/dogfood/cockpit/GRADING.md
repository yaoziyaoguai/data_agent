# 操作者独立判分

参考只来自已冻结的合成业务规范和独立查询。不得从产品本次结果反写预期，或把reference输入到产品模型。

## 状态

- not_run：未开始，所有模板初始状态。
- pass：本版本/本环境全部规定步骤和逐条断言均有对应证据。
- fail：前提成立，实际行为违反明确的口径或要求。
- partial：只完成部分目标、分支或产物，不能算全部通过。
- blocked_environment：角色、资料、服务、模型、受控故障或第二空间等前提缺失。
- blocked_authorization：本轮缺少相应收费或运维授权。
- inconclusive：超时、未知回执或证据不足，暂不能判定。

先报告各状态计数，再对同版本、同模式、完整执行的同类场景给分母。真实模型、UI、模型替身、离线SQL和工程协议证据分开，不能合成一个“准确率”。

## 数值不能替代语义判分

数值正确但分母、单位、条件或文字解释错误，不能整体pass。比率使用各自明确分母；端到端任务达成率用eligible轮次，ASR最终尝试率按题目指定有尝试轮次；重试、候选、槽位、动作尝试、TTS分段都不是新的用户交互。分组百分比和P95不能直接平均成总体。阶段耗时会并行或重叠，不能盲目相加成首播关键路径。

ASR服务成功不等于识别准确，NLU接受不等于意图正确，动作请求返回不等于确认执行成功，TTS生成不等于播报完成。取消、拒识、无语音、合法跳阶段、打断、缺测、迟到和未知回执分别表达。只有独立合成标签及匹配规范足够时，才能核对准确率。

表中车端对话/轮次与当前Data Agent会话/任务是两套身份，不能混用。车辆当前版本与交互发生时版本也不能互相替代。

## 最少证据

每项保存case_id、attempt_id、代码/资料指纹、实际角色和模型、原用户消息、步骤结果、最终SQL/参数、task/run/query/result/report/asset及版本、可定位证据文件、逐断言结论和理由。不能只写“正常”或贴没有上下文的截图。

参考SQL可以在本地只读合成库执行。若产品SQL列名不同，用明确的列映射解释等价性；不能凭输出数字“看起来差不多”判通过。参考中明确排序的结果按相应排序比较；无顺序语义的集合先规范排序。整数、NULL和身份必须精确，浮点只使用参考声明的容差。

## 持续流程

同一消息授权多SQL时逐条看实际状态；只完成A不能把A/C整项算通过。报告与方法必须保留实际采用的全部来源；创建成功不代表正文语义完整。来源失效、旧条件结果和未知回执不能因最后一句话好看而被抹掉。

修复、绕路、重试或模型切换分别记attempt，保留原失败。只有明确新证据支持时才复验，不无限改提示抽样。未实际触发压缩、取消或恢复时，不能称相关能力通过。
