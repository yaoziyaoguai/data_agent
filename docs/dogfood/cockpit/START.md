# 先确认资料，再从简单到复杂试用

本包围绕车端语音交互数据：入口 → 唤醒/VAD → ASR → NLU/槽位 → 多轮对话 → 技能路由 → 动作/回执 → TTS → 播报与打断。车辆、软件构建、语言和网络是背景维度，不是另一套泛座舱经营大盘。

## 开始前

读取仓库AGENTS.md、CURRENT最新增量、本包manifest.json和`.local/cockpit-dogfood/HANDOFF.md`环境交接。本包100项全部从not_run开始；准备资料、SQL可运行或旧版通过都不是本次产品通过。

核对实际commit、工作树、模型/思考档、Pi版本、检索/记忆模式、业务源目录和快照指纹。入口使用本机交接记录中的服务，不猜端口，不将mock回复当真实模型。实际身份和本地文件位置只放忽略目录，不把凭据写到本包。

表和文档必须完整可读：按当前manifest核对实体、字段、单位、NULL、粒度、PK/FK和各链路规则。前置数量完整只证明存在；有矛盾或关键前提缺失时记录，不自行编业务规则。

## 资料隔离

只有源目录knowledge-manifest.json明确允许的DDL、ETL和业务文档进入模型知识。以下内容只给操作者：本试用包、reference、场景expect、结果记录、评分、生成器、seed和独立预期。不得把答案作为“帮助模型的资料”补入记忆、Skill、公共案例或用户提问。

fixtures是专门允许操作输入的合成材料；按案例采用，不把整个fixtures目录一并灌入知识。示例语句和标识从零构造，无公司名称、原始音频或真实用户话术。

## 执行授权

本包不自行授予收费或运维权限。沿执行会话中已明确的用户授权、现有模型配置与原持久账本工作。没有真实模型授权时，把相关项记为blocked_authorization，完成无需授权的静态/UI部分，不用mock替代真实模型判分。

沿原规则：每条消息24次模型调用，连续临时失败3次停止；摘要、恢复、重试和结果解释仍属于原范围。不要另加默认累计费用/时间上限，也不要复制有限trial或更换ID绕过原限制。不使用本轮未获准的新供应商或高价模型。

所有故障、撤权、资料改版、删除、模型停用和角色调整，只作用于本轮隔离对象/运行环境。不要破坏用户当前会话和基线资料。未知回执按原身份查证，不盲目重发动作。

## 逐级推进

先跑P01–P09，再以S01→S02和一个语音口径澄清场景验证真实路径。环境与模型符合预期后，按L1–L6逐步增加多表、多轮和跨能力复杂度。需要时用build.py按级别或case ID读取，不一次加载全部手册及长日志。

depends_on表示需要前序产物，不要求前序整项必须pass。如果对象确已建立且可用，可注明原失败后继续；缺对象则blocked，不通过API代造来冒充前序模型成功。

同一条完整真实轨迹可以覆盖多个案例，但必须满足各自全部原消息、范围和断言并指向同一证据。不同语义变体或另一次成功不能洗掉原失败。

## 记录与结束

把records/results-template.json复制到.local/dogfood-runs/<run_id>/results.json。每步记录输入、可见答复、SQL和参数、对象/版本、工具回执与截图；每项及时落盘，每批写HANDOFF。所有失败attempt保留，不修改题目、参考或产品代码来制造通过。

试用Agent只试用、定位和报告，不修产品、不提交推送。最后100项状态之和必须为100，并分别列pass/fail/partial/blocked_environment/blocked_authorization/inconclusive/not_run。把同根因问题合并，保留所有受影响case与原轨迹。费用不足或中断时先记录在途与未知，再明确下一步。
