# 给执行 Agent 的 Prompt

请按当前仓库 `docs/dogfood/cockpit/` 的语音交互 Dogfood 包进行试用和报告，先不要修产品代码。

先读 `AGENTS.md`、`docs/CURRENT.md` 最新增量、本包 `README.md`、`START.md` 和 `manifest.json`。本包以唤醒/VAD、ASR候选、NLU槽位、多轮澄清、技能路由、动作与回执、TTS播报和打断为中心；车辆、版本、语言、网络仅为背景。不要套用旧零售或泛座舱用例。

先核对实际本地服务、模型/思考档、角色、资料源及快照指纹。源资料必须是 `docs/sources/cockpit`。本机连接和身份文件位置由忽略目录`.local/cockpit-dogfood/HANDOFF.md`提供，不把凭据打印、截图或写到报告。

全部100项从not_run开始，按L0–L6逐级执行。先用P01–P09、S01→S02及一个真实澄清场景确认路径，再扩展。用 `python3 docs/dogfood/cockpit/build.py --case <ID>` 或 `--level <N>` 分批读取，不一次加载整个长手册。按依赖保留必要对象；允许同一完整真实轨迹复用证据，不用相似题替代原题。

只采用本轮用户已经明确授权的模型、费用和运维范围。本文件不单独授权付费。继续每消息24次、连续临时失败3次规则，恢复/重试/摘要/结果唤醒沿原预算与操作身份。缺少某项授权时仅将相应案例记blocked_authorization，继续其他可做部分，不把mock当真实模型通过，不私自换供应商或重置有限trial。

真实用户功能从UI走。API或SQL只用于获准的隔离准备、读取持久状态和独立判分。维护、角色、资料改版、撤权、故障与清理只对本轮隔离对象操作，不能影响基线或用户其他数据。不能通过直接写库补做产品漏掉的步骤后声称模型通过。

`reference/`、场景expect、评分、结果、seed和生成器都不得进入产品模型的知识、记忆、Skill、案例或用户提问。只发送案例messages与允许的fixtures。没有独立标签时不要求模型编出准确率；没有精确时钟或断连区间时不要求虚构时延因果。

每项记录实际输入/答复、SQL/参数、对象版本、关键工具回执、截图/下载和逐断言理由。保留失败attempt，未知先查证。执行期间不改产品、资料、题目或预期，也不提交推送。每批更新HANDOFF；结束时给出100项状态分布、真实问题及最小复现、证据与置信度，区分实现、模型、环境和未实现范围。

若本轮只负责一批，用户另行指定精确case_id列表；其余保持not_run，不覆盖其他Agent的记录。
